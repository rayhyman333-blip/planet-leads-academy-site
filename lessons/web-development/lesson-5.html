This lesson teaches you JavaScript: the programming language that makes pages interactive. By the end you will declare variables, work with strings, numbers, and booleans, write functions, use conditionals and loops, and run code when the user clicks something. HTML is structure, CSS is appearance, JavaScript is behavior — the three layers of every page.

JavaScript runs inside a <script> tag, usually placed just before the closing </body> so the page content loads first:

<script>
console.log("Hello from JavaScript!");
</script>

console.log prints to the browser console (in developer tools) — your window into what the code is doing. Use it constantly while learning: when unsure what a value is, log it.

Variables store values. Prefer const for values that will not change and let for values that will: const siteName = "My Site"; let visitorCount = 0; visitorCount = visitorCount + 1;. (Older code uses var — you will see it, but write const and let.) Data types: strings ("hello", 'hello' — text in quotes), numbers (42, 3.14 — no quotes), booleans (true/false), plus arrays (ordered lists: const colors = ["red", "green", "blue"];) and objects (named values: const user = { name: "Ava", age: 30 };). Template literals join strings cleanly with backticks: const greeting = `Hello, ${user.name}!`; — the ${} inserts the value.

Arrays and objects deserve a closer look because you will use them constantly. Arrays are zero-indexed: colors[0] is "red", colors[2] is "blue", and colors.length tells you how many items there are (3). Add to the end with colors.push("yellow"); — now length is 4. Objects bundle related values under names: user.name reads "Ava", user.age reads 30, and you can add new properties anytime with user.city = "Austin";. Bracket notation works too — user["name"] — which is useful when the property name itself is stored in a variable. Reach for arrays for lists of similar things (menu items, gallery images, form entries) and objects for single things with multiple attributes (a user, a product, a submitted form's data). You will combine them endlessly: an array of objects is how most real data looks.

Functions package reusable logic:

function greet(name) {
return `Hello, ${name}!`;
}
console.log(greet("Ava")); // Hello, Ava!

Conditionals choose paths: if (age >= 18) { ... } else { ... }. Comparisons use === (strict equality — checks value and type) rather than ==, which does surprising type conversions beginners should avoid. Loops repeat: for (let i = 0; i < 3; i++) { console.log(i); } counts 0, 1, 2; arrays loop cleanly with for...of: for (const color of colors) { console.log(color); }.

Events connect code to the user. A button with an id, wired in JavaScript:

<button id="helloBtn">Say hello</button>
<script>
const btn = document.getElementById("helloBtn");
btn.addEventListener("click", function() {
alert("Hello! You clicked the button.");
});
</script>

addEventListener waits for the named event ("click", "submit", "input", "keydown") and runs your function when it happens. This pattern — find element, listen for event, run code — is the heartbeat of interactive pages, and Lesson 6 expands it into full DOM manipulation.

Two mistakes dominate this lesson. First, script running before the elements exist: if your <script> is in the <head> and tries getElementById on a button defined later in the body, it finds nothing. Put scripts at the end of the body (or wait for the DOMContentLoaded event). Second, the console is your diagnostic tool — when nothing happens, open it first. A red error message with a line number tells you exactly where to look; "Uncaught TypeError: Cannot read properties of null" almost always means getElementById found no element, usually a misspelled id.

Practice: Add a script to index.html that: (1) declares a const with your name and logs a greeting with a template literal; (2) defines a function add(a, b) that returns their sum and logs add(7, 5); (3) adds a button that, when clicked, asks for the visitor's name with prompt() and shows a personalized greeting with alert(). Open the console, click the button, and confirm each step works. Then intentionally misspell the button's id in the JavaScript, reload, read the console error, and fix it — reading errors calmly is a core developer skill.

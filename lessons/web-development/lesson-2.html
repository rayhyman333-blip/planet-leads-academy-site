This lesson teaches you the core HTML elements for structuring real pages. By the end you will use headings, paragraphs, links, images, and lists correctly; build a working form with labels and inputs; and organize a page with semantic section elements. HTML is a language of meaning: each tag says what its content is, and the browser (and search engines, and screen readers) treat it accordingly.

Headings run <h1> through <h6>. Use exactly one <h1> per page for the main topic, then <h2> for major sections, <h3> for subsections, and so on — like an outline. Never choose a heading level for its size; that is CSS's job (Lesson 3). Skipping from <h1> to <h4> confuses assistive technology that reads the page aloud. Paragraphs are <p>, and line breaks inside text use <br> (no closing tag needed — it is a void element, like <img> and <input>). Emphasis: <strong> means "important" (renders bold) and <em> means "stressed emphasis" (renders italic) — prefer these over the purely visual <b> and <i> because they carry meaning.

Links and images connect your page to the world. An anchor tag creates a link: <a href="about.html">About me</a> links to your own page, while <a href="https://example.com">Example</a> links outward (external addresses need the full https://). Add target="_blank" to open in a new tab for external links. Images use <img src="photo.jpg" alt="A description of the photo">: src is the file path, and alt is the text shown if the image cannot load and read aloud by screen readers — always write a real alt description, never leave it empty on meaningful images. Keep images in your my-site folder next to the HTML so src="photo.jpg" works; subfolders work too (src="images/photo.jpg").

Lists come in three flavors. Unordered lists (<ul>) for bullets, ordered lists (<ol>) for numbered steps, each with list items (<li>):

<ul>
<li>Apples</li>
<li>Bread</li>
<li>Cheese</li>
</ul>

A description list (<dl> with <dt> terms and <dd> descriptions) suits glossaries and FAQs. Nesting lists inside list items builds sub-menus and outlines — just keep the nesting tidy.

Forms collect input. Every input needs a <label> connected with matching for and id attributes — this is what makes the label clickable and the form accessible:

<form action="#" method="post">
<label for="name">Your name:</label>
<input type="text" id="name" name="name" required>
<label for="email">Email:</label>
<input type="email" id="email" name="email" required>
<label for="message">Message:</label>
<textarea id="message" name="message" rows="4"></textarea>
<button type="submit">Send</button>
</form>

Input types do real work for you: type="email" checks for an @ sign, type="number" shows a number picker, type="date" shows a calendar, and required blocks empty submission — all built into the browser, no JavaScript needed. Checkboxes, radio buttons (grouped by sharing one name), and <select> dropdowns cover the rest.

Finally, semantic page structure. Wrap your page in meaningful sections instead of bare <div>s: <header> for the top banner, <nav> for navigation links, <main> for the primary content, <section> for thematic groups, <article> for self-contained pieces, <aside> for sidebars, and <footer> for the bottom. A well-structured page is easier to style, easier to find in search, and usable by everyone.

Two mistakes to watch for. First, unclosed or wrongly nested tags: <p><strong>text</p></strong> is invalid — tags must close in reverse order of opening, like parentheses: <p><strong>text</strong></p>. Your browser's Inspect tool highlights broken nesting. Second, images that do not load: the cause is almost always the src path — check the filename spelling, the extension (.jpg vs .jpeg), and whether the image is actually in the folder you pointed to.

Practice: Rebuild your about.html as a complete structured page: a <header> with your name as <h1> and a <nav> linking to index.html and about.html, a <main> with two <section>s (each with an <h2>), one <ul> of skills and one <ol> of goals, an <img> with a real alt description, and a <footer> with a small copyright line. Then add the contact form above to index.html. Open both pages, click every link, submit the empty form to see the browser's built-in validation, and fix anything that does not work.

This lesson teaches you modern page layout: arranging elements in rows and columns with flexbox, and making pages adapt to phones, tablets, and desktops with responsive design. By the end you will build a navigation bar, a card grid, and a two-column layout with flexbox, and you will write media queries that reflow your site on small screens. Layout is where CSS turns from decoration into architecture.

Flexbox lays out the children of a container along one axis. Declare display: flex on the parent, and its children become flex items in a row. The essential properties: flex-direction (row or column — the main axis), justify-content (how items spread along the main axis: flex-start, center, space-between, space-around), align-items (how items line up on the cross axis: stretch, center, flex-start, flex-end), gap (space between items — far cleaner than margins), and flex-wrap (wrap lets items flow onto new lines instead of squishing). A navigation bar is the canonical example:

nav ul {
display: flex;
gap: 24px;
list-style: none;
padding: 0;
}

A card grid adds wrapping: .card-grid { display: flex; flex-wrap: wrap; gap: 16px; } with .card { flex: 1 1 250px; } — each card grows and shrinks but never below 250px, so you get as many columns as fit. A classic two-column layout: .layout { display: flex; gap: 24px; } with main { flex: 3; } and aside { flex: 1; } — the flex numbers divide available space proportionally (3:1). Centering, the ancient CSS riddle, is now trivial: display: flex; justify-content: center; align-items: center; on the parent.

Responsive design means one site that works everywhere, and it rests on three techniques. First, the viewport meta tag — without it, phones render your page at desktop width and shrink it: <meta name="viewport" content="width=device-width, initial-scale=1"> goes in every page's head, always. Second, fluid sizing: images get max-width: 100%; height: auto; so they never overflow their container; layouts use percentages and flex instead of fixed pixel widths. Third, media queries — CSS rules that apply only under conditions, almost always max-width breakpoints:

/* phones: stack the columns */
@media (max-width: 700px) {
.layout { flex-direction: column; }
nav ul { flex-direction: column; gap: 8px; }
}

Design mobile-first when you can: write the base CSS for the small screen, then add min-width queries that enhance the layout as space grows. It is easier to add columns than to remove them, and it forces you to prioritize content.

Relative units make responsive typography smooth. px is absolute; em scales with the parent's font size (compounding in nested elements — a known trap); rem scales with the root font size (predictable — 1.5rem is always 1.5 times the base). Set body { font-size: 16px; } (or leave the browser default) and size headings in rem: h1 { font-size: 2rem; }. Percentages suit widths; rem suits type and spacing.

Two mistakes to watch for. First, forgetting the viewport meta tag — the number one cause of "my site looks tiny on my phone". Check every page's head. Second, fixed-width elements overflowing small screens: a 900px-wide image or table inside a 360px phone screen breaks the layout sideways. Apply max-width: 100% to images and test every page at phone width using your browser's device toolbar (in developer tools).

Practice: Rebuild your about.html layout with flexbox: a horizontal nav bar (logo left, links right — hint: margin-left: auto on the link group pushes it right), a two-column main/aside section, and a three-card row that wraps. Add the viewport meta tag if it is missing. Then write a max-width: 700px media query that stacks everything into one column and enlarges tap targets (nav links get padding: 12px). Test at desktop width and at phone width in the device toolbar, and fix every horizontal scrollbar you find.

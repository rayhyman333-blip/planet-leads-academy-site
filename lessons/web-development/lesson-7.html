This lesson teaches you to handle forms with JavaScript: intercepting submission, reading and validating input, showing helpful errors, and building a complete small project. By the end you will build a validated contact form and a working tip calculator. Forms are where users give your site data — getting them right is one of the most practical skills in web development.

Browsers validate forms for free (Lesson 2: required, type="email", minlength), but JavaScript validation gives you custom rules and friendlier errors. The key move: listen for the form's submit event and call event.preventDefault() to stop the browser's default page-reload submission, then run your own logic:

<form id="contactForm" novalidate>
<label for="email">Email:</label>
<input type="email" id="email">
<span class="error" id="emailError"></span>
<button type="submit">Send</button>
</form>
<script>
const form = document.getElementById("contactForm");
form.addEventListener("submit", function(event) {
event.preventDefault();
const email = document.getElementById("email").value.trim();
const errorEl = document.getElementById("emailError");
if (!email.includes("@") || !email.includes(".")) {
errorEl.textContent = "Please enter a valid email address.";
return;
}
errorEl.textContent = "";
document.getElementById("thanks").textContent = "Thanks! We will reply to " + email;
form.reset();
});
</script>

(The novalidate attribute turns off the browser's built-in popups so your custom messages show instead — use one system, not both.) Validation principles: check on submit (and optionally as the user types, after the first error); show the error next to the field it belongs to; clear errors as soon as the input becomes valid; never trust client-side validation alone for anything important — real applications re-check on the server, but for this course the browser is the whole world.

Live validation — checking as the user types — makes forms feel responsive, but use it carefully. The input event fires on every keystroke, which is perfect for clearing an error the moment the input becomes valid, and terrible for flagging errors mid-word (nobody likes being told their half-typed email is wrong). The professional pattern: validate on submit, then once a field has shown an error, also validate it on input so the error clears the instant the user fixes it:

document.getElementById('email').addEventListener('input', function() {
const value = this.value.trim();
const ok = value.includes('@') && value.includes('.');
document.getElementById('emailError').textContent = ok ? '' : 'Please enter a valid email address.';
});

Errors appear at submit and disappear as they are fixed — the form feels alive without nagging. Combine this with the submit handler above and you have validation users actually enjoy: strict where it matters, forgiving everywhere else.

Now the project: a tip calculator. Requirements in plain language first: user enters a bill amount and a tip percentage, clicks calculate, sees the tip and total; invalid input shows a friendly error instead of a weird number. HTML: two number inputs, a button, a result paragraph, an error span. JavaScript:

function calculateTip() {
const bill = parseFloat(document.getElementById("bill").value);
const percent = parseFloat(document.getElementById("percent").value);
const errorEl = document.getElementById("tipError");
if (isNaN(bill) || bill <= 0) {
errorEl.textContent = "Enter a bill amount greater than zero.";
return;
}
if (isNaN(percent) || percent < 0) {
errorEl.textContent = "Enter a tip percentage of zero or more.";
return;
}
errorEl.textContent = "";
const tip = bill * (percent / 100);
const total = bill + tip;
document.getElementById("tipResult").textContent =
`Tip: $${tip.toFixed(2)} — Total: $${total.toFixed(2)}`;
}
document.getElementById("calcBtn").addEventListener("click", calculateTip);

Note the guards: parseFloat turns text into numbers (isNaN catches non-numeric input), zero/negative bills are rejected with words, and toFixed(2) formats money to two decimals — floating-point math like 0.1 + 0.2 producing 0.30000000000000004 is a famous quirk, and toFixed is the standard fix for display.

Two mistakes to avoid. First, forgetting preventDefault and watching the page reload, wiping your results — if your form "flashes and resets", this is the cause. Second, doing math on strings: input values are always text, so "10" + "5" gives "105" (concatenation) instead of 15. Convert with parseFloat/parseInt or Number() before any arithmetic, and validate with isNaN.

Practice: Build the tip calculator as tip.html with the full validation above, styled with your stylesheet. Test the complete matrix: valid input (100, 15 → $15.00 / $115.00), empty inputs, text input ("abc"), zero bill, negative percentage — confirm each shows the right message and valid input clears errors. Then extend it once: add a "split between N people" input that also shows per-person amounts. When every case behaves, you have built a real interactive application.

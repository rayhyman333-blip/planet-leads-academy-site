This lesson teaches you CSS: the language that controls how your HTML looks. By the end you will write selectors that target elements, classes, and ids; set colors, fonts, and spacing; link a stylesheet to your pages; and predict layout using the box model. HTML is the skeleton; CSS is everything visual. The two stay in separate files so you can redesign a whole site without touching its content.

CSS rules have three parts: a selector (what to style), a property (what aspect), and a value. p { color: navy; } makes every paragraph navy. Write CSS in a separate file — styles.css in your my-site folder — and link it from each page's <head>: <link rel="stylesheet" href="styles.css">. One stylesheet shared by all pages means one place to change your site's look. (You can also write CSS inside a <style> tag in the head while experimenting, but move it to the file for real projects.)

Selectors, from broad to precise. Element selectors target every instance: h1 { ... }, p { ... }. Class selectors target any element with that class — reusable styles: .highlight { background: yellow; } applies to <p class="highlight"> and any other tagged element. Id selectors target one unique element: #main-title { ... } for <h1 id="main-title"> — use ids sparingly, mostly as JavaScript hooks (Lesson 6). Combine and refine: nav a { ... } styles links inside navigation only; h2.section-title targets h2 elements with that class; a:hover styles links when the mouse is over them. When two rules conflict, the more specific selector wins, and equal specificity goes to the later rule — this cascade is where the name "Cascading Style Sheets" comes from.

Colors and text. Set colors with names (navy, tomato), hex codes (#1a73e8 — six digits, pairs for red/green/blue), or rgb() values. color sets text color; background-color sets the fill behind it. Typography: font-family: Georgia, serif; lists fallback fonts in order — always end with a generic family (serif, sans-serif, monospace) so the page degrades gracefully. font-size: 18px; sets size (px is precise; Lesson 4 introduces flexible units), font-weight: bold;, line-height: 1.6; gives breathing room between lines, and text-align: center; centers text. Keep body text at a comfortable size with generous line height — readability beats decoration.

The box model governs all layout. Every element is a box with four layers, outside in: margin (space outside the box, separating it from neighbors), border (the edge), padding (space inside, between the border and the content), and the content itself. So this rule:

.card {
width: 300px;
padding: 20px;
border: 2px solid #333;
margin: 16px;
}

creates a 300px content area with 20px of inner space, a 2px border, and 16px of separation from neighbors. The classic beginner shock: by default, width sets only the content width, so the visible box is wider than 300px. Fix it globally with the universal box-sizing rule, which every project should start with:

* { box-sizing: border-box; }

Now padding and border count inside the declared width — 300px means 300px total. Margins collapse vertically (two stacked 16px margins make 16px of space, not 32) — surprising once, then natural.

Two mistakes dominate this lesson. First, the stylesheet not loading: check the <link> tag's href path and filename spelling, confirm styles.css is saved, and hard-refresh the browser (Ctrl+Shift+R) to bypass the cache. Second, styles "not working" that are actually being overridden: a more specific selector or a later rule is winning — use Inspect, find your element, and read the crossed-out rules to see exactly which rule beat yours.

Practice: Create styles.css and link it from both your pages. Style the body with a readable font, comfortable line height, and a max-width of 800px centered with margin: 0 auto. Style your header with a background color and your nav links with spacing and a hover color. Build one .card class (padding, border, rounded corners with border-radius: 8px) and apply it to two sections. Then deliberately break something — misspell a property — and use Inspect to find the browser ignoring it. Fix it. Understanding failure is part of the skill.

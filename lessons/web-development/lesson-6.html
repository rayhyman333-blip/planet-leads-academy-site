This lesson teaches you the DOM (Document Object Model): the browser's live representation of your page that JavaScript can read and change. By the end you will find elements, change their text, styles, and classes, create new elements, and build interactive widgets like counters, toggles, and lists. This is where pages stop being documents and start being applications.

The DOM is a tree of nodes mirroring your HTML: document is the root, each tag is an element node, text inside is a text node. JavaScript reaches into this tree. The main finders: document.getElementById("price") grabs one element by its unique id; document.querySelector(".card") grabs the first element matching any CSS selector; document.querySelectorAll("li") grabs all matching elements as a list you can loop over. querySelector is the most flexible — any selector you learned in Lesson 3 works: "#menu a", "input[type=email]", ".faq p".

Once found, elements are yours to change. textContent reads or sets the text inside: const el = document.getElementById("msg"); el.textContent = "Saved!";. innerHTML sets HTML markup (powerful but risky with user input — prefer textContent for plain text). Styles change through the style property using camelCase names: el.style.backgroundColor = "lightgreen"; el.style.fontSize = "20px";. Better still, toggle classes and let CSS do the work: el.classList.add("hidden"); el.classList.remove("hidden"); el.classList.toggle("active"); — with .hidden { display: none; } in your stylesheet. Class toggling keeps styling in CSS where it belongs and makes state changes one clean line.

You can also build elements from nothing: document.createElement("li") makes a new list item, you set its textContent, then parent.appendChild(newItem) attaches it. Removing: parent.removeChild(child), or the simpler child.remove(). Reading user input: const value = document.getElementById("name").value; — .value holds what the user typed. Put it together and you have the classic interactive widget — a click counter:

<p>Clicks: <span id="count">0</span></p>
<button id="clickBtn">Click me</button>
<script>
let clicks = 0;
const countSpan = document.getElementById("count");
document.getElementById("clickBtn").addEventListener("click", function() {
clicks = clicks + 1;
countSpan.textContent = clicks;
});
</script>

A variable holds the state, the listener updates it, and the DOM displays it. Nearly every interactive feature — tabs, accordions, image galleries, task lists — is this pattern with more elements. Another staple: theme toggle. A button toggles a dark class on <body>, and CSS defines body.dark { background: #222; color: #eee; } — one classList.toggle line, whole page re-themed.

querySelectorAll shines for repeated widgets like FAQ accordions. Give each question button the class "faq-q" and each answer the class "faq-a" (hidden by default with CSS). One loop wires them all:

document.querySelectorAll('.faq-q').forEach(function(btn) {
btn.addEventListener('click', function() {
btn.nextElementSibling.classList.toggle('hidden');
});
});

Each button toggles only its own answer — nextElementSibling finds the element right after the button in the HTML. This is event handling at scale: ten questions, one small loop, zero repeated code. Notice the Lesson 5 pattern recurring: find elements, listen for events, update state and display. The DOM rewards this uniformity — once the pattern clicks, every widget is a variation on it.

Two mistakes to watch for. First, stale references: if you replace an element's innerHTML, any variables pointing at its old children now point at detached nodes — re-query after structural changes. Second, adding listeners inside loops incorrectly or adding the same listener twice (double-firing handlers): attach each listener once, at setup time, and use event delegation (one listener on a parent, checking event.target) for lists of similar items.

Practice: Build a "reading list" widget on about.html: an input, an "Add book" button, and an empty <ul>. Clicking the button (or pressing Enter — listen for it) appends the input's text as a new <li> with a small "remove" button beside it that deletes its own item when clicked; clear the input after each add and ignore empty submissions. Then add a theme-toggle button that toggles a dark class on the body with matching CSS. Test every path: add three books, remove the middle one, toggle the theme twice, and submit empty input to confirm it is ignored.

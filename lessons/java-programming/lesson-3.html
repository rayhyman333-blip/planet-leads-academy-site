This lesson teaches your programs to make decisions: to choose one path when a condition is true and another when it is false. By the end you will write if, else if, and else statements, combine conditions with logical operators, compare values correctly, and use switch for choosing between many options. Decisions are what turn a program that always does the same thing into a program that responds to its input, and nearly every script you write from now on will use them.

An if statement runs a block of code only when its condition is true:

int age = 20;
if (age >= 18) {
System.out.println("You are an adult.");
} else {
System.out.println("You are under 18.");
}

Notice the structure: the word if, then the condition in parentheses, then the code to run inside curly braces. The else block runs when the condition is false. For more than two paths, add else if branches between them:

int score = 85;
if (score >= 90) {
System.out.println("Grade: A");
} else if (score >= 80) {
System.out.println("Grade: B");
} else if (score >= 70) {
System.out.println("Grade: C");
} else {
System.out.println("Grade: below C");
}

Java checks the branches top to bottom and runs the first one whose condition is true, then skips the rest. So order matters: the highest threshold must come first, because if you checked score >= 70 first, a score of 95 would stop there and be graded C. Each condition must be a boolean value, true or false, or an expression that produces one, such as a comparison. Always write the braces, even for a one-line block: it prevents a classic bug where a second line you add later looks like part of the if but is not.

Comparison operators produce boolean values. The operator == checks equality, != checks inequality, and <, >, <=, >= compare size. So 5 == 5 is true, 5 != 5 is false, and "apple" cannot be compared with < in the way numbers can. One of the most common beginner errors in any language is using a single = where == belongs: age = 18 stores 18 into age, while age == 18 asks whether age equals 18. In Java this mistake usually fails to compile inside an if, which is good, because the compiler catches it. Logical operators combine boolean values: && means and, and is true only when both sides are true; || means or, and is true when either side is true; ! means not, and flips a value. So if (age >= 18 && hasTicket) runs only when both parts are true, and if (isWeekend || isHoliday) runs when either one is true. You can group conditions with parentheses to make the grouping clear: if ((age < 12) || (age >= 65)) gives a discount to children and older adults.

Comparing text needs special care in Java. The == operator on Strings checks whether two variables refer to the same object in memory, not whether the words match, so it can give the wrong answer even when the text looks identical. Always compare String contents with the equals method: name.equals("Maya") returns true when the text matches. There is also equalsIgnoreCase, which ignores capital letters, so "maya".equalsIgnoreCase("Maya") is true. This is one of those rules that feels strange until you have been bitten by it once, and then you never forget it. For numbers, chars, and booleans, == works exactly as you expect, so the rule is simple: numbers use ==, text uses equals.

The switch statement is a tidy way to choose between many fixed options for one value. It is handy for menus, days of the week, or single-character commands:

int day = 3;
switch (day) {
case 1:
System.out.println("Monday");
break;
case 2:
System.out.println("Tuesday");
break;
case 3:
System.out.println("Wednesday");
break;
default:
System.out.println("Another day");
}

Each case labels one value, and break stops the switch after that case runs. Forgetting break is a famous bug: without it, Java falls through and runs the next case too, printing two days. The default case runs when no case matches, and it is good practice to always include one. Use switch when you are testing one value against a list of exact matches; use if and else if when the conditions are ranges or complex combinations.

Two mistakes to watch for in this lesson. First, the assignment-versus-comparison mix-up already mentioned: read = as gets and == as equals every time. Second, the semicolon after the if condition: writing if (age >= 18); with a semicolon ends the if statement right there, so the next block runs no matter what. The if line must not end with a semicolon. When a program seems to ignore your condition entirely, check for that stray semicolon first.

Practice: Write a program called TicketPrice.java. Declare an int age and a boolean isStudent, and set them to values you choose. Use if, else if, and else to compute a ticket price: children under 12 pay 5, students pay 8, adults aged 65 and over pay 7, and everyone else pays 12. Print the price. Then change the values of age and isStudent and run the program again several times, checking each branch in turn: a child, a student, an older adult, and a regular adult. As a second exercise, write a small switch program that takes an int from 1 to 7 and prints the day of the week, with a default for any other number, and test it with 1, 5, and 9.

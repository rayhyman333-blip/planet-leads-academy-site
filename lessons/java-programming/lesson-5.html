This lesson teaches you to package code into methods: named, reusable blocks that take inputs and produce outputs. By the end you will define methods with parameters and return values, call them from main and from each other, and understand the difference between printing a value and returning it. You will also learn about method overloading and variable scope. Methods are the single most important organizing tool in programming: they let you write a piece of logic once, test it once, and reuse it everywhere without copying and pasting.

You have already been using methods: System.out.println and String.equals are methods that someone else wrote. Defining your own looks like this, placed inside the class but outside main:

public static double celsiusToFahrenheit(double celsius) {
return (celsius * 9.0 / 5.0) + 32.0;
}

The first word, public, means the method can be used from other classes. The word static means it belongs to the class rather than to one particular object; Lesson 7 explains that distinction, and for now every method in this course is static so it can be called from main. The word double before the name is the return type: the kind of value this method gives back. The name follows Java naming style, starting with a lowercase letter and capitalizing each new word, which is called camel case. The parentheses hold parameters: the inputs the method expects, each with a type and a name. The body computes the result, and the return statement sends it back to the caller. Calling it looks like this:

double result = celsiusToFahrenheit(25.0);
System.out.println(result);

The argument 25.0 is passed in as the parameter celsius, the method computes 77.0, and that value is stored in result. A method can take several parameters, separated by commas, and the arguments you pass must match in number, order, and type. A method that returns nothing uses the return type void, like main itself, and it ends without a return statement, or with a bare return; to exit early.

The difference between printing and returning is the key idea of this lesson. Compare two versions of an addition method. One prints: public static void showSum(int a, int b) { System.out.println(a + b); }. The other returns: public static int add(int a, int b) { return a + b; }. The printing version shows 7 on the screen but gives nothing back, so the caller cannot use the 7 for anything else. The returning version hands 7 back, so the caller can store it, double it, or pass it to another method: int doubled = add(3, 4) * 2;. The rule of thumb is: print is for showing humans, return is for giving values back to your program so it can keep working with them. When your method computes something the rest of the program needs, a total, a converted value, a yes-or-no answer, return it. When it only needs to display something, print it. Methods can also call other methods, which is normal and encouraged: a method that describes a temperature can call celsiusToFahrenheit inside itself instead of repeating the formula.

Method overloading lets you define several methods with the same name but different parameter lists, and Java picks the right one by the arguments you pass. For example, you might have add(int a, int b) and add(double a, double b), or greet(String name) and greet(String name, String greeting). This keeps names simple while allowing flexibility. Parameters can also have sensible behavior built in: a method can check its inputs and handle edge cases, such as returning zero for a negative quantity, rather than trusting every caller to check first. Put that checking in one place, inside the method, and every caller benefits.

Scope determines where a variable can be seen. Variables created inside a method are local: they exist only while that method runs and are invisible outside it. Parameters are also local to their method. A variable declared in main cannot be seen inside another method, and a variable declared inside a helper method cannot be seen in main. This is a feature, not a limitation: it keeps methods independent, so you can understand and test each one on its own. Data flows into a method through its parameters and out through its return value, and that clear flow is what makes methods predictable. If two methods both need the same value, pass it as an argument to both rather than trying to share a variable between them.

Two mistakes to watch for. First, calling a method before you understand its return type: if a method returns a value and you ignore it, the work is wasted, and if a void method is used as if it returned something, the compiler will stop you. Always check the return type in the method header. Second, mismatched types in a call: passing a String where an int is expected, or passing two arguments to a method that takes three, are compile errors. Read the method header like a contract: it states exactly what goes in and what comes out, and the call must honor it.

Practice: Write a file called Converters.java with three static methods: celsiusToFahrenheit(double c) that returns (c * 9.0 / 5.0) + 32.0, milesToKm(double miles) that returns miles * 1.609, and describeTemperature(double c) that calls celsiusToFahrenheit and returns a String like "25.0C is 77.0F". Note how the third method calls the first: methods calling methods is normal. Then write a main method that asks the user for a Celsius temperature using a Scanner, converts the input, and prints the result of describeTemperature. To read a decimal, use input.nextDouble(). Test with 0, 25, and 100, and verify the outputs are 32.0, 77.0, and 212.0. As a stretch, add an overloaded describeTemperature that also takes a place name and returns a sentence naming the place.

Lesson 1: Setting Up Java and Your First Program

This lesson gets Java running on your computer and teaches you to write, compile, and run your first program. By the end you will know how to check whether Java is already installed, how to install a Java development kit if it is not, how to save a program in a plain text file, and how to compile it and run it from the command line. You will also learn the basic shape of every Java program. Run every example yourself as you read, because setup only becomes real when you see your own program print its first line.

First, check whether Java is already installed. Open a terminal or command prompt and type java -version, then press Enter. If you see a version number, Java is present. Also type javac -version and press Enter. The javac command is the compiler: it turns the code you write into a form the computer can run. You need both commands to work for this course. If either one is not recognized, you need to install a Java development kit, which includes both the runtime and the compiler. Download a current long-term-support release from the official Java download page or from your operating system's package manager, run the installer, and then close and reopen your terminal so it picks up the new commands. If the commands still are not recognized after installing, the installer may not have added Java to your system path; repeat the install step carefully, or check the installer's help page for your operating system.

With Java installed, write your first program. Open a plain text editor, type the following code exactly, and save the file as Hello.java. The file name must match the class name inside the program, including the capital H:

public class Hello { public static void main(String[] args) { System.out.println("Hello, world!"); System.out.println("Welcome to Java."); } }

Now, in your terminal, move to the folder where you saved the file and type javac Hello.java, then press Enter. If there are no errors, this creates a file called Hello.class in the same folder. Then type java Hello and press Enter. Both lines print. Notice that you compile with the file name including .java, but you run with just the class name, no extension. That distinction trips up many beginners, so say it to yourself as you type: compile the file, run the class.

Let us read the program line by line so none of it feels like magic. The first line, public class Hello, declares a class named Hello. In Java, all code lives inside classes, and a class is a blueprint that groups related code together. The second line, public static void main(String[] args), declares the main method: the starting point of the program. When you run java Hello, Java looks for this exact method and starts there. The words public, static, and void are part of the required spelling for now; you will understand each one properly in later lessons, and for now you can treat the whole main line as a fixed pattern you copy. Inside main, the two lines beginning System.out.println print text to the screen. The text is wrapped in double quotes, and each statement ends with a semicolon. Curly braces mark the beginning and end of the class and the method, and indentation is just for human readability: Java does not care about it, but your future self does.

Two beginner mistakes cause most Lesson 1 frustration. First, saving the file with the wrong name or extension: Hello.java must end in .java, not .txt, and the class name inside must match the file name exactly, including capital letters. If you save as hello.java with a lowercase h while the class is Hello, the compiler will complain. Second, typing java Hello.java to run the program: that tries to run a source file as if it were a class, and it fails. Compile with javac Hello.java, run with java Hello. When something fails, read the error message from the top: the compiler usually names the file and line number, and a missing semicolon on one line is often reported on the next line, so check the line above the reported one too.

Practice: Create a file called AboutMe.java with a class named AboutMe and a main method. Inside main, use three System.out.println statements to print your name, your favorite hobby, and one thing you want to build with Java. Compile it with javac AboutMe.java and run it with java AboutMe. Then, on purpose, remove one semicolon, compile again, and read the error message. Put the semicolon back, compile, and confirm it works. Finally, try running java AboutMe.java and read the error, so you recognize that mistake instantly if you make it again.

Lesson 2: Variables and Types

This lesson teaches you variables: named boxes that store values your program can use and change. By the end you will know the main Java types for whole numbers, decimal numbers, text, single characters, and true-or-false values; you will declare variables, assign values, combine them with operators, and print results. You will also learn how Java's strict typing protects you and where it catches beginners out. Variables appear in every program you will ever write, so make sure each example below runs on your machine before moving on.

A variable has a type, a name, and a value. The type says what kind of value it can hold, the name is how you refer to it, and the value is what it currently holds. You declare a variable by writing its type, then its name, then an equals sign and a value, ending with a semicolon:

int age = 30; double price = 12.50; String name = "Maya"; char grade = 'A'; boolean isOpen = true;

The int type holds whole numbers like 30, -3, and 1000. The double type holds numbers with a decimal point like 12.50 and 98.6. The String type, with a capital S, holds text in double quotes. The char type holds a single character in single quotes, like 'A' or '7'. The boolean type holds only true or false, written in lowercase. You can also declare first and assign later: int score; on one line, then score = 85; on a later line. But you must assign a value before you use a variable, or the compiler will stop you with an error saying the variable might not have been initialized. That is Java protecting you from using a value that was never set.

Java is statically typed, which means each variable keeps its type forever. Once you declare int age, age can only hold whole numbers. Trying to store text in it, like age = "thirty";, is a compile error, not a surprise at runtime. This strictness feels fussy at first, but it catches a whole category of mistakes before your program ever runs. There are two related types worth knowing now: long for very large whole numbers, and float for decimal numbers that use less memory, though double is the usual choice for decimals in beginner code. Type names matter in exact spelling and case: Int and int are different, and only lowercase int is a type. String is the one type name that starts with a capital letter, because it is a class, a fact Lesson 7 will explain.

Operators combine values into new values. Arithmetic operators work like a calculator: + adds, - subtracts, * multiplies, and / divides. Two are special: % gives the remainder after division, so 7 % 2 is 1, and that remainder operator is surprisingly useful for checking even and odd numbers or cycling through positions. Integer division is a classic trap: 7 / 2 in Java is 3, not 3.5, because dividing two ints gives an int and drops the fractional part. If you want 3.5, at least one side must be a double: 7.0 / 2 gives 3.5. The + operator on Strings joins them together: "Good " + "morning" gives "Good morning". You can also join text and numbers: "Age: " + age gives "Age: 30" because Java converts the number to text for the joining. You can change a variable with shorthand: age = age + 1; can be written age++; to add one, and total += 5; adds five to total. These shortcuts are common in real code, so learn to read them even if you write the long form at first.

Two mistakes dominate this lesson. First, using = when you mean ==. A single equals sign stores a value, while a double equals sign compares two values and gives true or false. In Lesson 3 you will write if (age == 18), and writing if (age = 18) instead is an error in Java. Read = as gets, as in age gets 30, and == as equals, and your brain will flag the mix-up. Second, mixing types without converting: String count = "5"; followed by count + 1 does not give 6, it gives the text "51", because + on text joins

instead of adding. To turn text into a number you convert explicitly, for example int count = Integer.parseInt("5");. The reverse, turning a number into text, happens automatically when you join it with a String using +, as shown above.

Practice: Write a program called Shop.java that declares variables for an item name (a String), its price (a double), and how many you are buying (an int). Compute the total cost in a new double variable, then print a sentence like "3 notebooks cost 15.0" using the variables, not typed-in numbers. Then add a second program section, or a second small program, that prints the results of 7 / 2, 7.0 / 2, 7 % 2, and 10 % 3, and write a one-line comment in your own words above each print explaining the result. A comment in Java starts with // and runs to the end of the line. Test your program with different prices and quantities and confirm the total changes correctly.

Lesson 3: Making Decisions with Conditionals

This lesson teaches your programs to make decisions: to choose one path when a condition is true and another when it is false. By the end you will write if, else if, and else statements, combine conditions with logical operators, compare values correctly, and use switch for choosing between many options. Decisions are what turn a program that always does the same thing into a program that responds to its input, and nearly every script you write from now on will use them.

An if statement runs a block of code only when its condition is true:

int age = 20; if (age >= 18) { System.out.println("You are an adult."); } else { System.out.println("You are under 18."); }

Notice the structure: the word if, then the condition in parentheses, then the code to run inside curly braces. The else block runs when the condition is false. For more than two paths, add else if branches between them:

int score = 85; if (score >= 90) { System.out.println("Grade: A"); } else if (score >= 80) { System.out.println("Grade: B"); } else if (score >= 70) { System.out.println("Grade: C"); } else { System.out.println("Grade: below C"); }

Java checks the branches top to bottom and runs the first one whose condition is true, then skips the rest. So order matters: the highest threshold must come first, because if you checked score >= 70 first, a score of 95 would stop there and be graded C. Each condition must be a boolean value, true or false, or an expression that produces one, such as a comparison. Always write the braces, even for a one-line block: it prevents a classic bug where a second line you add later looks like part of the if but is not.

Comparison operators produce boolean values. The operator == checks equality, != checks inequality, and <, >, <=, >= compare size. So 5 == 5 is true, 5 != 5 is false, and "apple" cannot be compared with < in the way numbers can. One of the most common beginner errors in any language is using a single = where == belongs: age = 18 stores 18 into age, while age == 18 asks whether age equals 18. In Java this mistake usually fails to compile inside an if, which is good, because the compiler catches it. Logical operators combine boolean values: && means and, and is true only when both sides are true; || means or, and is true when either side is true; ! means not, and flips a value. So if (age >= 18 && hasTicket) runs only when both parts are true, and if (isWeekend || isHoliday) runs when either one is true. You can group conditions with parentheses to make the grouping clear: if ((age < 12) || (age >= 65)) gives a discount to children and older adults.

Comparing text needs special care in Java. The == operator on Strings checks whether two variables refer to the same object in memory, not whether the words match, so it can give the wrong answer even when the text looks identical. Always compare String contents with the equals method: name.equals("Maya") returns true when the text matches. There is also equalsIgnoreCase, which ignores capital letters, so "maya".equalsIgnoreCase("Maya") is true. This is one of those rules that feels strange until you have been bitten by it once, and then you never forget it. For numbers, chars, and booleans, == works exactly as you expect, so the rule is simple: numbers use ==, text uses equals.

The switch statement is a tidy way to choose between many fixed options for one value. It is handy for menus, days of the week, or single-character commands:

int day = 3; switch (day) { case 1: System.out.println("Monday"); break; case 2: System.out.println("Tuesday"); break; case 3: System.out.println("Wednesday"); break; default: System.out.println("Another day"); }

Each case labels one value, and break stops the switch after that case runs. Forgetting break is a famous bug: without it, Java falls through and runs the next case too, printing two days. The default case runs when no case matches, and it is good practice to always include one. Use switch when you are testing one value against a list of exact matches; use if and else if when the conditions are ranges or complex combinations.

Two mistakes to watch for in this lesson. First, the assignment-versus-comparison mix-up already mentioned: read = as gets and == as equals every time. Second, the semicolon after the if condition: writing if (age >= 18); with a semicolon ends the if statement right there, so the next block runs no matter what. The if line must not end with a semicolon. When a program seems to ignore your condition entirely, check for that stray semicolon first.

Practice: Write a program called TicketPrice.java. Declare an int age and a boolean isStudent, and set them to values you choose. Use if, else if, and else to compute a ticket price: children under 12 pay 5, students pay 8, adults aged 65 and over pay 7, and everyone else pays 12. Print the price. Then change the values of age and isStudent and run the program again several times, checking each branch in turn: a child, a student, an older adult, and a regular adult. As a second exercise, write a small switch program that takes an int from 1 to 7 and prints the day of the week, with a default for any other number, and test it with 1, 5, and 9.

Lesson 4: Repeating Work with Loops

This lesson teaches loops: code that repeats a block while a condition holds or for a fixed number of times. By the end you will write for loops and while loops, choose between them, control loops with break and continue, and use loops to process collections of values. Loops are what let a program handle ten items as easily as ten thousand, and they are the engine inside almost every real program.

A for loop is best when you know how many times you want to repeat, or you want to count through a range. Its header has three parts separated by semicolons: a starting value, a condition to keep going, and an update step:

for (int i = 0; i < 5; i++) { System.out.println("Count: " + i); }

This prints Count: 0 through Count: 4, five lines in total. The variable i starts at 0, the loop runs while i < 5, and i++ adds one after each pass. That zero start surprises beginners, so remember it clearly: i < 5 with i starting at 0 gives five passes, 0 through 4. If you need 1 through 5, write for (int i = 1; i <= 5; i++). The difference between < and <= is the classic off-by-one error: one extra or one missing pass. When a loop runs the wrong number of times, add a temporary print of i inside it and watch the actual values; seeing the sequence usually reveals the mistake at once. The loop variable i exists only inside the loop, so you cannot use it after the closing brace.

A while loop repeats as long as its condition stays true, which makes it ideal when you do not know in advance how many repetitions you need:

int attempts = 0; int secret = 7; int guess = 0; while (guess != secret) { guess = 7; attempts++; } System.out.println("Guessed in " + attempts + " tries.");

In a real program the guess would come from user input, which you will add in the practice exercise. The danger with while is the infinite loop: if the condition can never become false, the loop runs forever. Always make sure something inside the loop body moves the condition toward false. In the example, guess changes each pass. If you ever get stuck in an infinite loop, stop the program in your terminal and check what should have changed the condition but did not. A do-while loop is a small variation that runs the body once before checking the condition, which is handy for menus that must show at least once:

int choice; do { System.out.println("Menu: 1) Play 2) Quit"); choice = 1; } while (choice != 2);

Two tools give you finer control inside any loop: break exits the loop immediately, and continue skips the rest of the current pass and jumps to the next one. For example, break can end a guessing game the moment the player wins, and continue can skip zero values while processing a list of numbers. Use them sparingly and clearly: a loop with many breaks scattered through it is hard to read, so prefer a clear condition when you can.

Loops become powerful when they accumulate a result. A common pattern is to start a total at zero, loop through values, and add each one:

int[] scores = {85, 92, 78, 90}; int total = 0; for (int i = 0; i < scores.length; i++) { total += scores[i]; } System.out.println("Total: " + total); System.out.println("Average: " + (total / 4.0));

The array in this example is a preview of Lesson 6: a list of values held under one name, read by position. The loop visits each position in turn. Notice the average divides by 4.0, not 4, so the result is a

decimal: dividing two ints would drop the fraction, as Lesson 2 warned. Another common pattern is searching: loop through values, and when you find the one you want, remember its position and break. A third is counting matches: start a counter at zero and add one each time a value meets a condition. Learn these three patterns, total, search, and count, and you will recognize them in code for years.

Two mistakes dominate this lesson. First, the off-by-one error already mentioned: i <= scores.length runs one pass too many and tries to read past the end of the array, which crashes with an index error. The correct bound is i < scores.length. Second, forgetting to update the loop variable in a while loop, or updating it in the wrong place, which creates an infinite loop. A good habit is to write the update step immediately after writing the while line, before filling in the rest of the body.

Practice: Write a program called TimesTable.java that uses a for loop to print the 7-times table from 7 x 1 to 7 x 12, one line per row. Then write a second program called GuessingGame.java that picks a secret number in the code, uses a while loop to keep asking the user for a guess until they get it right, prints Too high or Too low after each wrong guess using if and else if, counts the attempts, and prints how many tries it took when they win. To read user input, use a Scanner: import java.util.Scanner; at the top, create Scanner input = new Scanner(System.in); before the loop, read guesses with int guess = input.nextInt(); inside the loop, and close the scanner with input.close(); at the end. Test the game with guesses below, above, and equal to the secret.

Lesson 5: Methods — Reusable Blocks of Code

This lesson teaches you to package code into methods: named, reusable blocks that take inputs and produce outputs. By the end you will define methods with parameters and return values, call them from main and from each other, and understand the difference between printing a value and returning it. You will also learn about method overloading and variable scope. Methods are the single most important organizing tool in programming: they let you write a piece of logic once, test it once, and reuse it everywhere without copying and pasting.

You have already been using methods: System.out.println and String.equals are methods that someone else wrote. Defining your own looks like this, placed inside the class but outside main:

public static double celsiusToFahrenheit(double celsius) { return (celsius * 9.0 / 5.0) + 32.0; }

The first word, public, means the method can be used from other classes. The word static means it belongs to the class rather than to one particular object; Lesson 7 explains that distinction, and for now every method in this course is static so it can be called from main. The word double before the name is the return type: the kind of value this method gives back. The name follows Java naming style, starting with a lowercase letter and capitalizing each new word, which is called camel case. The parentheses hold parameters: the inputs the method expects, each with a type and a name. The body computes the result, and the return statement sends it back to the caller. Calling it looks like this:

double result = celsiusToFahrenheit(25.0); System.out.println(result);

The argument 25.0 is passed in as the parameter celsius, the method computes 77.0, and that value is stored in result. A method can take several parameters, separated by commas, and the arguments you pass must match in number, order, and type. A method that returns nothing uses the return type void, like main itself, and it ends without a return statement, or with a bare return; to exit early.

The difference between printing and returning is the key idea of this lesson. Compare two versions of an addition method. One prints: public static void showSum(int a, int b) { System.out.println(a + b); }. The other returns: public static int add(int a, int b) { return a + b; }. The printing version shows 7 on the screen but gives nothing back, so the caller cannot use the 7 for anything else. The returning version hands 7 back, so the caller can store it, double it, or pass it to another method: int doubled = add(3, 4) * 2;. The rule of thumb is: print is for showing humans, return is for giving values back to your program so it can keep working with them. When your method computes something the rest of the program needs, a total, a converted value, a yes-or-no answer, return it. When it only needs to display something, print it. Methods can also call other methods, which is normal and encouraged: a method that describes a temperature can call celsiusToFahrenheit inside itself instead of repeating the formula.

Method overloading lets you define several methods with the same name but different parameter lists, and Java picks the right one by the arguments you pass. For example, you might have add(int a, int b) and add(double a, double b), or greet(String name) and greet(String name, String greeting). This keeps names simple while allowing flexibility. Parameters can also have sensible behavior built in: a method can check its inputs and handle edge cases, such as returning zero for a negative quantity, rather than trusting every caller to check first. Put that checking in one place, inside the method, and every caller benefits.

Scope determines where a variable can be seen. Variables created inside a method are local: they exist only while that method runs and are invisible outside it. Parameters are also local to their method. A variable declared in main cannot be seen inside another method, and a variable declared inside a helper method cannot be seen in main. This is a feature, not a limitation: it keeps methods independent, so you can understand and test each one on its own. Data flows into a method through its parameters and out through its return value, and that clear flow is what makes methods predictable. If two methods both need the same value, pass it as an argument to both rather than trying to share a variable between them.

Two mistakes to watch for. First, calling a method before you understand its return type: if a method returns a value and you ignore it, the work is wasted, and if a void method is used as if it returned something, the compiler will stop you. Always check the return type in the method header. Second, mismatched types in a call: passing a String where an int is expected, or passing two arguments to a method that takes three, are compile errors. Read the method header like a contract: it states exactly what goes in and what comes out, and the call must honor it.

Practice: Write a file called Converters.java with three static methods: celsiusToFahrenheit(double c) that returns (c * 9.0 / 5.0) + 32.0, milesToKm(double miles) that returns miles * 1.609, and describeTemperature(double c) that calls celsiusToFahrenheit and returns a String like "25.0C is 77.0F". Note how the third method calls the first: methods calling methods is normal. Then write a main method that asks the user for a Celsius temperature using a Scanner, converts the input, and prints the result of describeTemperature. To read a decimal, use input.nextDouble(). Test with 0, 25, and 100, and verify the outputs are 32.0, 77.0, and 212.0. As a stretch, add an overloaded describeTemperature that also takes a place name and returns a sentence naming the place.

Lesson 6: Arrays — Working with Many Values

This lesson teaches arrays: ordered collections that hold many values of the same type under one name. By the end you will create arrays, read and change items by position, find the length of an array, loop through arrays with for and enhanced for loops, and pass arrays to methods. Arrays are what let programs handle real quantities of data: instead of one variable per score, you keep a hundred scores in a single structure and process them with loops from Lesson 4.

An array is declared with square brackets after the type, and created with new and a size, or filled at once with values in braces:

int[] scores = new int[5]; int[] grades = {85, 92, 78, 90, 88}; String[] names = {"Ava", "Ben", "Cara"};

The first form creates an array of five ints, all starting at zero. The second form creates an array already holding those five numbers. Items are numbered starting at 0, so grades[0] is 85, grades[2] is 78, and grades[4] is 88. You read an item with the same bracket notation and change one by assigning to a position: grades[1] = 95; replaces 92 with 95. The length of an array is available as a field, not a method: grades.length is 5, with no parentheses. That distinction matters, because String has a length() method with parentheses while arrays use a length field without them, and mixing the two up is a common compile error.

Looping is where arrays shine. A standard for loop visits each position by index, which is what you need when the position itself matters:

for (int i = 0; i < grades.length; i++) { System.out.println("Score " + i + ": " + grades[i]); }

An enhanced for loop, also called a for-each loop, visits each value directly and is simpler when you only need the values:

for (int grade : grades) { System.out.println("Score: " + grade); }

Read the second form as: for each grade in grades, do this. Use the standard loop when you need the index, for example to change items or to compare neighbors; use the enhanced loop when you only need to read values. Both patterns appear constantly in real code, so learn to read both fluently. A very common use is finding a total, a highest value, or an average: start a variable before the loop, update it inside, and use it after the loop, exactly as Lesson 4 showed with totals.

Arrays can be passed to methods just like single values, and methods can return arrays too. A method that computes an average might look like this:

public static double average(int[] values) { int total = 0; for (int value : values) { total += value; } return total / (double) values.length; }

The parameter int[] values accepts any int array, so the same method works for five scores or five hundred. Notice the cast (double) before values.length: it converts the length to a double so the division gives a decimal result instead of dropping the fraction, as Lesson 2 warned. Inside a method, an array parameter refers to the same array the caller passed, so changing items inside the method changes them for the caller too. That shared behavior is useful but worth knowing: if a method should not change the caller's data, it should work on a copy.

Two-dimensional arrays hold tables of values, such as a grid of seats or a month of daily readings, and they are simply arrays of arrays:

int[][] grid = { {1, 2, 3}, {4, 5, 6} };

Here grid[0][1] is 2, the second item in the first row. You process them with nested loops: an outer loop for rows and an inner loop for columns. Two-dimensional arrays are not needed for the final project, but recognizing them will help when you meet real tables of data in later learning.

Two mistakes are classic here. First, the off-by-one index error: the last item of an array with five items is grades[4], not grades[5], and grades[5] crashes the program with an ArrayIndexOutOfBoundsException. When in doubt, use grades[grades.length - 1] for the last item. Second, comparing arrays with == or equals and expecting it to compare contents: == on arrays checks whether they are the same array object, not whether they hold the same values. To compare contents element by element, loop through and compare each position, or use a library helper designed for that purpose.

Practice: Write a program called GradeBook.java. Create an int array with eight scores of your choice. Write a method findHighest that takes an int array and returns the largest value, a method findLowest that returns the smallest, and a method average that returns the average as a double. In main, print the highest, lowest, and average. Then add a loop that counts how many scores are 90 or above and prints that count. Test with your scores, then change two scores and run again to confirm the results update. As a stretch, create a String array of student names in the same order as the scores and print each name beside its score using one loop over the index.

Lesson 7: Classes and Objects

This lesson teaches classes and objects: the heart of Java. By the end you will define a class with fields and methods, create objects from it with new, use constructors to set starting values, and understand how objects differ from the simple values you have used so far. You will also learn encapsulation, the practice of keeping an object's data safe behind methods. Classes let you model real things, a book, a bank account, a player, as a bundle of data plus the actions that belong to it, and that modeling skill is what makes larger programs manageable.

A class is a blueprint; an object is one thing built from that blueprint. You have already seen one class, Hello, and the main class of every program. Here is a small class that models a book:

public class Book { private String title; private String author; private int pages;

public Book(String title, String author, int pages) { this.title = title; this.author = author; this.pages = pages; }

public String getTitle() { return title; }

public String getAuthor() { return author; }

public int getPages() { return pages; }

public String describe() { return title + " by " + author + " (" + pages + " pages)"; } }

The fields at the top, title, author, and pages, are the data each Book object holds. The word private means these fields can only be touched from inside the Book class itself, which protects them from accidental changes elsewhere. The Book method with the same name as the class is a constructor: it runs when an object is created and sets the starting values. Inside it, this.title means the field of this object, as opposed to the parameter title, which is why this is needed when the names match. The getTitle, getAuthor, and getPages methods are getters: they let other code read a field without changing it. The describe method returns a readable sentence about the book. Notice that describe and the getters have no static word: they belong to one particular object, and they work on that object's fields.

Creating and using an object looks like this, in a different class with a main method:

Book first = new Book("Dune", "Frank Herbert", 412); System.out.println(first.describe()); System.out.println(first.getTitle());

The word new creates the object and runs the constructor with the arguments you pass. The variable first holds a reference to that object, and the dot notation calls its methods: first.describe() asks that specific book to describe itself. A second object, Book second = new Book("Emma", "Jane Austen", 320);, is independent: changing one book's data never affects the other, because each object holds its own fields. That independence is the point of objects. The main method is static, which means it belongs to the class, not to an object, so it cannot directly use non-static fields; it must create an object first and then work through it. That is why every program so far has had static methods called from main, and why this lesson's objects are created inside main before their methods are used.

Encapsulation is the discipline of keeping fields private and giving other code controlled access through methods. Why bother? Because methods can check and protect the data. A Book with negative pages

makes no sense, so a setter for pages could refuse negative values:

public void setPages(int pages) { if (pages > 0) { this.pages = pages; } }

Callers set pages through setPages, and bad values are rejected in one place instead of being checked everywhere the field is used. Getters and setters together are called accessors, and they are the standard Java style: fields private, access through methods. You will also meet the toString method, a special method Java calls automatically when an object is printed: if you define public String toString() returning a readable description, then System.out.println(first); prints that description instead of a cryptic memory reference. Defining toString is good practice for every class you write.

Objects can also hold other objects and arrays, which is how real models are built. A library catalog could be a class holding an array of Book objects, with methods to add a book and search by title. That is exactly the final project in Lesson 8, and it works because each Book knows how to describe itself while the catalog knows how to manage the collection. One more idea completes the picture: a class can have static fields and methods shared by all objects, such as a counter of how many books have been created, but most of your classes will use instance fields and methods like the ones above, with each object holding its own data.

Two mistakes to watch for. First, forgetting new: writing Book first; declares a variable but creates no object, and calling first.describe() on it crashes with a NullPointerException, because there is no object yet. Always create with new before using. Second, comparing objects with == when you mean to compare their contents: first == second checks whether they are the same object in memory, not whether they hold the same title and author. For Strings, use equals, as Lesson 3 taught, and for your own classes, compare the fields that matter, such as first.getTitle().equals(second.getTitle()).

Then create a second file called LibraryTest.java with a main method that creates three Book objects with titles, authors, and page counts you choose, and prints each book's description using describe(). Then add a getPages call to print the longest book's page count by comparing the three values with if statements. Run the program and confirm all three descriptions print correctly. As a stretch, add a setPages method with the positive-value check shown above, call it with a negative number, and confirm the page count does not change.

Lesson 8: Final Project — A Small Book Catalog

This final lesson puts the whole course together in one project: a small book catalog program that stores books, lists them, and searches for a title. By the end you will have combined classes, arrays, loops, methods, conditionals, and user input in one working program, and tested it like a user would. It closes with a map of where to go next. Start every project by listing features in plain language before writing code, because a clear feature list turns a big task into small steps you already know how to take.

Our catalog needs four features. First, add a book: the user types a title, an author, and a page count, and the program stores a new Book object. Second, list all books, printing each description. Third, search by title and print the matching book, or a clear message when nothing matches. Fourth, quit cleanly. Each feature maps to a lesson: input with a Scanner from Lesson 4, conditionals from Lesson 3, loops and arrays from Lessons 4 and 6, methods from Lesson 5, and the Book class from Lesson 7. Asking which lesson taught this piece is how you break big projects down, and it is a habit that will serve you in every project after this course.

The design has two classes. Book is the class from Lesson 7, unchanged, with its private fields, constructor, getters, and describe method. Catalog is a new class that holds the collection and the operations on it. Because this course has not yet taught resizable collections, the catalog uses a fixed-size array with a count of how many slots are actually filled, a pattern you will meet often in beginner code:

public class Catalog { private Book[] books; private int count;

public Catalog(int capacity) { books = new Book[capacity]; count = 0; }

public void addBook(Book book) { if (count < books.length) { books[count] = book; count++; } else { System.out.println("The catalog is full."); } }

public void listBooks() { if (count == 0) { System.out.println("No books yet."); return; } for (int i = 0; i < count; i++) { System.out.println(books[i].describe()); } }

public Book findByTitle(String title) { for (int i = 0; i < count; i++) { if (books[i].getTitle().equalsIgnoreCase(title)) { return books[i]; } } return null; } }

Read this carefully, because every line uses a lesson skill. The constructor creates the array and sets count to zero. addBook stores the book in the next free slot and advances the count, but refuses when the catalog is full, instead of crashing. listBooks loops only over the filled slots, i < count, not the whole array, because the empty slots hold nothing. findByTitle loops through the filled books, compares titles with equalsIgnoreCase so capital letters do not matter, returns the match at once, and returns null when nothing matches. Returning null to mean not found is a standard convention, and the caller must check for it before using the result.

The main class ties it together with a menu loop:

public class CatalogApp { public static void main(String[] args) { Catalog catalog = new Catalog(20); java.util.Scanner input = new java.util.Scanner(System.in); while (true) { System.out.println("1) Add 2) List 3) Search 4) Quit"); System.out.print("Choose: "); int choice = input.nextInt(); input.nextLine(); if (choice == 1) { System.out.print("Title: "); String title = input.nextLine(); System.out.print("Author: ");

String author = input.nextLine(); System.out.print("Pages: "); int pages = input.nextInt(); input.nextLine(); catalog.addBook(new Book(title, author, pages)); } else if (choice == 2) { catalog.listBooks(); } else if (choice == 3) { System.out.print("Search title: "); String title = input.nextLine(); Book found = catalog.findByTitle(title); if (found == null) { System.out.println("No book with that title."); } else { System.out.println(found.describe()); } } else if (choice == 4) { System.out.println("Goodbye!"); break; } else { System.out.println("Unknown choice, try 1-4."); } } input.close(); } }

Two details deserve attention. After nextInt, the program calls input.nextLine() once to consume the leftover line break, because nextInt reads the number but leaves the Enter keystroke behind, and the next nextLine would otherwise read an empty line. That is a famous Scanner trap, and now you know the fix. Also notice the architecture: main owns the loop and the user interaction, Catalog owns the data and the operations, and Book owns its own description. Each class has one job, each method does one thing, and the program grows by adding small methods, not by rewriting.

Test the complete cycle like a user would: add three books, list them, search for one that exists, search for one that does not, and quit. Then add books until the catalog is full and confirm it reports that it is full instead of crashing. Two project-level mistakes to watch for: forgetting the null check after findByTitle, which crashes when a search misses, and looping over the whole array instead of only the filled count, which crashes on empty slots. Both are fixed by the patterns shown above.

Where to go next depends on what excited you. If modeling real things thrilled you, learn inheritance and interfaces, which let classes share behavior and define contracts. If data handling appealed to you, learn resizable collections and file handling so your catalog can save its books between runs. If you want clickable things, graphical interfaces and web frameworks turn Java into applications people use with a mouse. Whatever you choose, the method stays the same: small project, break into steps, test each step, read errors calmly. You have the complete foundation; the rest is practice.

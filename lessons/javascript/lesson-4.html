This lesson teaches you the Document Object Model: JavaScript's live map of the web page, and the tool you use to change what visitors see. By the end you will select elements by id and with CSS-style selectors, read and change their text, adjust their styles, and create brand-new elements from code. The DOM is what turns JavaScript from a console curiosity into the language of interactive pages — every dynamic website you have ever used runs on these operations.

The DOM is the browser's tree-shaped representation of your HTML: every tag becomes a node you can reach from JavaScript. To work with an element, first give it an id in the HTML, then grab it:

<h1 id="title">Welcome</h1>
<p id="message">Loading...</p>

<script>
const titleEl = document.getElementById("title");
const msgEl = document.querySelector("#message");
console.log(titleEl.textContent); // Welcome
</script>

document.getElementById grabs one element by its id, while document.querySelector takes any CSS selector — "#message" for an id, ".warning" for a class, "button" for a tag — and returns the first match (querySelectorAll returns all matches). Once you hold an element, textContent reads or sets its text: msgEl.textContent = "Hello, Ava!"; rewrites the paragraph instantly. Prefer textContent over innerHTML for plain text: innerHTML interprets the string as HTML, which is powerful but dangerous with user-supplied text, while textContent treats everything as literal characters and is always safe. innerHTML has legitimate uses — inserting your own static markup, like building a card from a template literal — but treat any string containing user input as textContent-only territory.

Changing styles is just as direct — every CSS property is available in camelCase on the element's style object:

titleEl.style.color = "darkblue";
titleEl.style.fontSize = "40px";
msgEl.classList.add("highlight");

Note backgroundColor instead of background-color: CSS's hyphens become camelCase in JavaScript. The classList approach is often cleaner than inline styles: define a .highlight class in a <style> block, then add or remove it with classList.add() and classList.remove(), or flip it with classList.toggle(). This keeps your styling in CSS where it belongs and your JavaScript focused on behavior — a separation professionals maintain strictly.

You can also build elements from scratch, which is how apps render lists of data:

const listEl = document.getElementById("tasks");
const item = document.createElement("li");
item.textContent = "Buy milk";
item.classList.add("task");
listEl.appendChild(item);

document.createElement("li") builds a new list item, you configure it like any selected element, and appendChild attaches it inside the list. This create-configure-attach pattern is the heart of dynamic pages: your data lives in arrays and objects (Lesson 3), and a render function turns that data into elements. You can set several properties before attaching — text, class, even nested children — and nothing appears on the page until appendChild runs, which lets you build complex structures offscreen and insert them in one step. The capstone app in Lesson 8 is essentially this pattern plus events.

Two mistakes dominate DOM work. First, running your script before the elements exist: if the script tag sits in the head and tries getElementById("title"), it gets null because the body has not loaded yet. The simple fix is placing your script tag at the end of the body, right before </body>, so all elements exist when it runs. Second, calling methods on null: when a selector finds nothing, you get null, and null.textContent crashes with "cannot read properties of null". When that error appears, your selector is wrong or the element is missing — console.log the variable first and confirm it holds an element before touching it.

Practice: Create profile.html with an h1 (id="name"), a paragraph (id="bio"), and an empty ul (id="hobbies"). Write a script at the end of the body that: sets the h1's text to your name, sets the bio paragraph to two sentences about you, changes the h1's color, and creates three li elements from an array of your hobbies ["reading", "cycling", "cooking"] using a for...of loop with createElement and appendChild. Open the page and confirm everything renders. Then, in the console, try document.querySelector("#does-not-exist") and observe the null — then try setting .textContent on it to see the exact error, so you recognize it instantly in future lessons.

This lesson teaches you the building blocks every JavaScript program is made of: the core data types, the operators that combine them, and if/else statements for making decisions. By the end you will know the difference between strings, numbers, booleans, null, and undefined; you will use strict equality to avoid JavaScript's most famous trap; and you will write programs that choose different paths based on conditions. These ideas appear in every lesson after this one, so run each example in your console before moving on.

JavaScript has a small set of core types you will use constantly. A string is text in quotes: "hello", 'JavaScript', "42". A number covers both integers and decimals: 7, 3.5, -20 — JavaScript does not separate the two the way some languages do. A boolean is true or false, written lowercase. Then come the two "empty" values: null means "intentionally no value" (you set it on purpose), while undefined means "no value has been assigned yet" (JavaScript's default for untouched variables). The typeof operator tells you what you are holding: typeof "hello" gives "string", typeof 42 gives "number", typeof true gives "boolean". Types matter because JavaScript treats "42" (text) and 42 (a number) very differently, as you will see with operators next.

Arithmetic operators work like a calculator: + - * /, plus % for remainder (7 % 2 gives 1) and ** for powers (2 ** 3 gives 8). The + operator on strings joins them, called concatenation: "Good " + "morning" gives "Good morning". Here is JavaScript's famous trap: "5" + 3 gives "53", not 8, because + with a string converts the other side to text. To convert deliberately, use Number("5") to get 5 and String(42) to get "42". Now the equality trap: JavaScript has two kinds. Loose equality == converts types before comparing, so "5" == 5 is true — usually not what you want. Strict equality === compares without converting, so "5" === 5 is false. The rule professionals follow: always use === and !==, never == and !=, and an entire category of mysterious bugs disappears.

Comparison operators ask questions and answer with booleans: === checks equality, !== checks inequality, and < > <= >= compare size. Logical operators combine them: && means "and" (true only if both sides are true), || means "or" (true if either side is true), and ! flips a value. So age >= 18 && hasTicket gives true only when both hold. An if statement runs a block only when its condition is true:

const age = Number(prompt("Enter your age:"));
if (age >= 18) {
console.log("You are an adult.");
} else {
console.log("You are under 18.");
}

Note the parentheses around the condition and the curly braces marking each block — every indented statement between the braces belongs to that branch. For more paths, add else if branches: they are checked top to bottom and the first true one runs. The prompt() function here shows a pop-up asking for input and returns whatever was typed as a string, which is why we wrap it in Number() — the same string-input catch you would expect from any language.

Two mistakes dominate this lesson. First, using == instead of ===: "0" == false is true under loose equality, a genuinely baffling result that strict equality avoids entirely. If a comparison behaves impossibly, check which equality operator you used. Second, the assignment-in-condition slip: if (x = 5) assigns 5 to x and is always truthy, while if (x === 5) actually compares. Read = as "gets" and === as "is exactly" and your brain will flag the mix-up. A related gotcha: prompt() always returns a string, so comparing its result with a number using === fails unless you convert first with Number().

Practice: In your console, evaluate each of these and make sure you can explain the result before checking: "10" + 5, 10 + 5, Number("10") + 5, "5" === 5, "5" == 5, 0 === false, !true, and (7 > 3) && (2 < 1). Then create grade.html with a script that uses prompt() to ask for a test score, converts it with Number(), and logs "Grade: A" for 90+, "Grade: B" for 80+, "Grade: C" for 70+, and "Grade: below C" otherwise, using if/else if/else. Test it with 95, 82, and 64, and also test typing a non-number to see what happens — note the result, because handling that gracefully is a skill you will build on later.

This lesson gets you running JavaScript with zero installation, using the browser you already have. By the end you will know how to open the developer console and run code instantly, how to put a script inside a web page with script tags, and how to store values in variables with let and const. You will also write your first real code: console.log() for showing output. Everything in this lesson is about getting comfortable with the tools, so run every example yourself as you read.

JavaScript was born in the browser, which means your setup is already done. Open your browser, press F12 (or right-click any page and choose Inspect), and click the Console tab. You will see a prompt where you can type JavaScript and press Enter to run it immediately. Try typing console.log("Hello, world!") and pressing Enter — the message appears in the console. Try 2 + 3 and you will see 5. The console is your scratchpad for the whole course: whenever you wonder what a piece of code does, test it here in seconds instead of guessing. Nothing you type in the console changes the website permanently — reloading the page wipes it clean, so experiment freely.

The console is great for experiments, but real JavaScript lives inside web pages. Create a file called hello.html in a plain text editor, type the following, save it, and open it in your browser by double-clicking the file:

<!DOCTYPE html>
<html>
<body>
<h1>My first script</h1>
<script>
console.log("Hello from the page!");
console.log("2 + 3 is", 2 + 3);
</script>
</body>
</html>

The script tags mark where JavaScript lives inside the HTML. When the browser loads the page, it runs the code between them top to bottom. Open the console (F12) with this page open and you will see both messages — the page itself shows the heading, while the console shows your script's output. That split is normal: console.log() is a developer tool for seeing what your code is doing, and you will use it in every lesson to check your work.

Variables store values under names so you can reuse them. JavaScript has two main ways to declare them:

let name = "Maya";
let age = 30;
const birthYear = 1995;

Use let for values that will change (age = 31 later is fine) and const for values that should never be reassigned — trying birthYear = 2000 after declaring it const is an error. The const habit protects you: most values in a program never need to change, and const makes accidental changes impossible. Names follow the same rules as in most languages: letters, digits, underscores, and dollar signs, but no starting with a digit and no spaces. JavaScript convention writes multi-word names in camelCase — firstName, totalPrice — so adopt that style from day one. Like Python, JavaScript is case-sensitive: Age and age are different variables.

One more console trick that will save you hours: when something goes wrong, the console shows the error in red with a line number. Clicking the line number jumps to the failing code. Get into the habit of keeping the console open whenever you test a page — silent pages hide their errors, but the console always tells the truth.

Two beginner mistakes cause most Lesson 1 frustration. First, quoting: console.log("hi') fails because the opening double quote must close with a double quote. Pick one style per string and match it. Second, forgetting to save the file before reloading the browser, then wondering why nothing changed — the browser only knows about the saved version, so save, then reload, then check the console. If your script "does nothing," those two checks solve it most of the time.

Practice: Create greeting.html with a script that declares a const called name holding your name, a let called hobby holding your favorite hobby, and uses console.log() to print two lines, for example "Hi, I'm ..." and "I enjoy ...". Open the page, open the console, and confirm both lines appear. Then, in the console itself (not the file), experiment: type let testScore = 95; then testScore + 5; then const city = "Austin"; then try city = "Denver"; and read the error message. Notice how the console tells you assignment to a constant is not allowed — reading errors calmly is a skill you will use in every lesson.

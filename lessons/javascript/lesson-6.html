This lesson teaches the modern JavaScript features that make code shorter and clearer: arrow functions, template literals, and destructuring, plus a few companion tools. By the end you will rewrite callbacks as one-line arrows, build strings with embedded expressions instead of messy concatenation, and pull values out of objects and arrays in a single statement. You will see these features in nearly every real-world codebase, so fluency here is what makes other people's code readable to you.

Arrow functions are a compact way to write functions, and they shine as event callbacks:

// traditional
btn.addEventListener("click", function () {
console.log("clicked");
});

// arrow
btn.addEventListener("click", () => {
console.log("clicked");
});

The () => syntax replaces function (). With a single parameter the parentheses are optional — x => x * 2 — and with a single expression the braces and return are implied: const double = x => x * 2; means "take x, return x * 2". Multi-line arrows keep braces and an explicit return. One caution: arrows handle the special this value differently from traditional functions, treating it as the surrounding context instead of the element that fired the event. For the event handlers in this course you do not need this at all — but if you ever copy code that uses this inside a handler, know that switching it to an arrow can change its meaning, so leave traditional functions in place there.

Template literals replace fiddly string concatenation. They use backticks instead of quotes, and ${} embeds any expression:

const name = "Ava";
const unread = 3;
const msg = `Hello, ${name}! You have ${unread} unread messages.`;
console.log(msg); // Hello, Ava! You have 3 unread messages.

Compare that with "Hello, " + name + "! You have " + unread + " unread messages." — the template version reads like the final sentence. The ${} can hold any expression: ${unread + 1}, ${user.name.toUpperCase()}. Backticks also allow multi-line strings, so HTML snippets stay readable: const card = `<div class="card"><h2>${title}</h2><p>${body}</p></div>`;. From now on, prefer templates whenever a string contains variables.

Destructuring unpacks values in one move. From objects:

const user = { name: "Ava", age: 30, city: "Austin" };
const { name, age } = user;
console.log(name); // Ava

The variable names must match the keys. From arrays, position matters instead: const [first, second] = scores; grabs the first two items, and you can skip with commas: const [, runnerUp] = scores;. Function parameters destructure too — function showUser({ name, city }) — which makes it obvious which properties a function needs. Combined with the spread operator (...), you get effortless copies and merges: const updated = { ...user, age: 31 }; copies user with a new age, and const all = [...listA, ...listB]; joins arrays. Spread copies are shallow but perfectly adequate for the data shapes in this course.

Two mistakes catch beginners here. First, using regular quotes with ${}: "Hello, ${name}" prints the literal characters ${name} — interpolation only works inside backticks, so when variables refuse to fill in, check the quote character. Second, destructuring a missing property gives undefined silently: const { email } = user where user has no email key leaves email undefined, and using it later crashes far from the real cause. When a destructured value is unexpectedly undefined, verify the key name against the object — spelling and case must match exactly.

Practice: Rewrite the like-button code from Lesson 5 using an arrow function and a template literal for the button text (`Like (${likes})`). Then, in the console, practice destructuring: create const order = { id: 101, item: "headphones", price: 59.99, qty: 2 }; and use destructuring plus a template literal to log "Order 101: 2 x headphones = $119.98" with the total computed as ${price * qty} inside the string. Next, merge two arrays with spread and log the result. Finally, convert one of your Lesson 3 functions to an arrow function assigned to a const, call it, and confirm identical behavior — this cements when arrows are a safe swap.

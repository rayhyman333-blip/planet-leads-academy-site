This lesson teaches your pages to respond to users through events: the browser's way of announcing that something happened. By the end you will listen for clicks, react to typing as it happens, handle form submissions without reloading the page, and read information from the event object. Events are what make pages feel alive — without them, Lesson 4's DOM skills can only produce static pages that never react.

An event listener waits for something to happen on an element, then runs your function:

<button id="likeBtn">Like (0)</button>
<script>
const btn = document.getElementById("likeBtn");
let likes = 0;
btn.addEventListener("click", function () {
likes = likes + 1;
btn.textContent = "Like (" + likes + ")";
});
</script>

addEventListener takes the event name ("click") and a callback function that runs each time the event fires. The variable likes persists between clicks because it lives outside the callback — each click reads the current value, adds one, and rewrites the button's text. This pattern (state in a variable, event updates state, DOM re-renders) underlies every counter, toggle, and like button on the web. You can attach multiple listeners to the same element, and one callback can update several elements at once.

The input event fires on every keystroke inside a text field, which enables live feedback like character counters:

<label>Your message: <input id="msg" type="text"></label>
<p id="count">0 / 140</p>
<script>
const field = document.getElementById("msg");
const count = document.getElementById("count");
field.addEventListener("input", function () {
count.textContent = field.value.length + " / 140";
});
</script>

The .value property holds what the user typed. Reading it inside the input handler means the count updates with every keystroke — try it and watch. This immediate loop (user acts, event fires, page updates) is the signature feel of modern web apps, and it is built entirely from pieces you already know: selection, properties, and text updates.

Forms need one special technique. A form's submit event reloads the page by default, wiping your JavaScript state — to handle submission in code, you must cancel that default behavior:

<form id="taskForm">
<label>New task: <input id="taskInput" type="text"></label>
<button type="submit">Add</button>
</form>
<ul id="taskList"></ul>
<script>
const form = document.getElementById("taskForm");
const input = document.getElementById("taskInput");
const list = document.getElementById("taskList");
form.addEventListener("submit", function (event) {
event.preventDefault();
const text = input.value.trim();
if (text === "") { return; }
const item = document.createElement("li");
item.textContent = text;
list.appendChild(item);
input.value = "";
});
</script>

The event object, received as the callback's parameter, describes what happened; event.preventDefault() stops the browser's default reload. We trim whitespace and ignore empty submissions, create the list item with Lesson 4's pattern, and clear the field for the next entry. This is a miniature version of the capstone app — the only things missing are persistence and delete buttons, both coming in Lesson 8.

Two mistakes are classic here. First, forgetting preventDefault on submit: the page reloads, your added items vanish, and it looks like the code "didn't work" — it did work, then the reload erased it. If form handling ever seems to do nothing, check for preventDefault first. Second, attaching a listener to null because the id in getElementById does not match the HTML — ids are case-sensitive, so "taskForm" and "taskform" are different. When a button "does nothing," console.log the element right after selecting it; null means the selection failed, not the listener.

Practice: Create counter.html with three buttons ("Decrease", "Reset", "Increase") and a paragraph showing a number starting at 0. One listener per button should update the number and re-render the paragraph — decrease must not go below 0 (use an if). Then create signup.html with a form containing a name field and an email field plus a paragraph for messages. On submit, prevent the default reload; if either field is empty, show "Please fill in both fields." in the message paragraph; otherwise show "Thanks, <name>! We will write to <email>." and clear the form. Test every path, including submitting with empty fields and watching the page stay put.

This final lesson puts the whole course together in one capstone project: a complete interactive to-do app that adds tasks, marks them complete, deletes them, and saves everything in the browser so tasks survive reloads. By the end you will have combined DOM selection, events, modern JavaScript, and persistent storage in one page, and tested it like a user would. It closes with a map of where to go next.

Start every project by listing features in plain language before writing code. Our app needs five: 1) add a task from a form; 2) display all tasks as a list; 3) toggle a task complete/incomplete; 4) delete a task; 5) save tasks in the browser and reload them at startup. Each maps to a lesson: forms and events (Lesson 5), DOM creation (Lesson 4), arrays of objects (Lesson 3), template literals and arrows (Lesson 6), JSON for storage (Lesson 7). Asking which lesson taught a piece is how you break big projects down.

The data layer is an array of task objects plus two persistence functions. localStorage is a small key-value store built into every browser that survives page reloads — but it only stores strings, so we convert with JSON:

const STORAGE_KEY = "my-tasks-v1";

function loadTasks() {
try {
const saved = localStorage.getItem(STORAGE_KEY);
return saved ? JSON.parse(saved) : [];
} catch (error) {
return [];
}
}

function saveTasks(tasks) {
localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks));
}

Each task is { text: "Buy milk", done: false }. loadTasks handles the first visit (nothing saved returns []) and even corrupted data (parse failure returns [] instead of crashing). Test in the console by saving a sample array and loading it back.

Rendering turns the data into elements, and every user action follows the same cycle: update the array, save it, re-render:

let tasks = loadTasks();
const listEl = document.getElementById("taskList");

function render() {
listEl.textContent = "";
tasks.forEach((task, index) => {
const item = document.createElement("li");
const label = document.createElement("span");
label.textContent = task.text;
if (task.done) { label.style.textDecoration = "line-through"; }
const toggleBtn = document.createElement("button");
toggleBtn.textContent = task.done ? "Undo" : "Done";
toggleBtn.addEventListener("click", () => {
tasks[index].done = !tasks[index].done;
saveTasks(tasks);
render();
});
const delBtn = document.createElement("button");
delBtn.textContent = "Delete";
delBtn.addEventListener("click", () => {
tasks = tasks.filter((t, i) => i !== index);
saveTasks(tasks);
render();
});
item.append(label, toggleBtn, delBtn);
listEl.appendChild(item);
});
}

document.getElementById("taskForm").addEventListener("submit", (event) => {
event.preventDefault();
const input = document.getElementById("taskInput");
const text = input.value.trim();
if (text === "") { return; }
tasks.push({ text: text, done: false });
saveTasks(tasks);
render();
input.value = "";
});

render();

Notice the architecture: tasks is the single source of truth, render() is the only code that touches the DOM list, and every change (add, toggle, delete) updates the array, saves, then re-renders. The filter() call for deletion keeps every task except the clicked index — a pattern worth memorizing.

Two capstone-level mistakes to watch for. First, forgetting to call saveTasks after a change: toggling works on screen but reloads lose it — the rule is that every function mutating tasks saves before returning. Second, stale indexes: render() rebuilds all buttons fresh each time, so each button's closure captures the correct index. Updating elements in place instead would let indexes drift and toggle the wrong task — which is why the rebuild pattern is recommended.

Natural extensions, each an evening's work: an All / Active / Completed filter, an edit button, a remaining-tasks counter, or due dates. Each reuses the same architecture — update the array, save, re-render — which is the real lesson: apps grow by adding small pieces, not by rewriting.

Where to go next depends on what excited you. If interactivity thrilled you, deepen DOM and event skills, then explore a UI framework like React or Vue, which organize bigger apps around the same state-render ideas. If data appealed to you, combine Lesson 7's fetching with rendering for live-data apps — weather displays, search tools, dashboards. If you want JavaScript outside the browser, Node.js lets the same language power servers and pairs naturally with Python backends like Flask. Whatever you choose, the method stays the same: small project, break into steps, test each step, read console errors calmly. You have the complete foundation; the rest is practice.

Practice: Build the full app in tasks.html from the feature list above, typing it yourself. Test the complete cycle: add three tasks, toggle one complete, delete another, reload the page, and confirm the remaining tasks survived (open DevTools > Application > Local Storage to see the saved JSON). Then add ONE extension of your choice — the remaining-tasks counter is the most instructive — and verify it updates on every action. When it all works, you have finished the course: a working, persistent, interactive web app written entirely by you.

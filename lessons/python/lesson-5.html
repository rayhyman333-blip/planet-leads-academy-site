This lesson teaches you Python's four core collection types — containers that hold multiple values. By the end you will create and manipulate lists, look up values in dictionaries by key, understand when tuples and sets are the right choice, and loop over collections with for. Collections are what let programs handle real-world quantities of data: instead of one variable per item, you keep hundreds of items in a single structure and process them with loops and functions from the previous lessons.

A list is an ordered, changeable collection written with square brackets: scores = [85, 92, 78, 90]. Items are numbered starting at 0, so scores[0] is 85 and scores[2] is 78. You can read the length with len(scores), add items with scores.append(88), remove by value with scores.remove(78), or grab and remove the last item with scores.pop(). Lists can hold mixed types, but keeping one type per list makes your code easier to reason about. Looping is where lists shine: for score in scores: visits each item in order. Slicing grabs a section — scores[1:3] gives [92, 78] — handy for "first five" or "everything after the header" style tasks.

A dictionary stores key-value pairs inside curly braces: person = {"name": "Ava", "age": 30, "city": "Austin"}. Instead of positions, you look things up by key: person["name"] gives "Ava". Add or change entries with person["email"] = "ava@example.com", remove with del person["city"], and check existence safely with person.get("phone", "unknown") — get() returns a default instead of crashing when the key is missing, which makes it the safer choice for lookups. Dictionaries model real things beautifully: a contact has a name, phone, and email; a product has a price and a stock count. Loop over keys with for key in person:, over values with for value in person.values():, and over both with for key, value in person.items():. The expense tracker in Lesson 8 stores each expense as a dictionary inside a list — a pattern you will see in real programs everywhere.

A tuple is like a list that cannot be changed, written with parentheses: point = (10, 20). You read items the same way — point[0] is 10 — but point[0] = 5 is an error. Use tuples for fixed collections that should never change accidentally: coordinates, RGB colors, or a function's multiple return values. In fact, a function can return several values at once — return width, height actually returns one tuple — and the caller can unpack it: w, h = get_size(). A set is an unordered collection of unique values written with curly braces: tags = {"python", "coding", "python"} automatically becomes {"python", "coding"}, dropping the duplicate. Sets answer membership questions fast ("python" in tags) and do math-like operations: set_a | set_b unions them, set_a & set_b intersects them. Reach for a set whenever duplicates would be wrong or you need fast "is it in there" checks.

Choosing between them gets easier with a simple guide. Need order and the ability to change items? List. Need to look things up by name rather than position? Dictionary. Have values that must never change? Tuple. Need uniqueness or membership tests? Set. Beginners often force everything into lists, then write awkward code searching for items by position — if you catch yourself keeping a parallel list of names just to find the matching data, that is a dictionary's job.

Two mistakes are classic here. First, the off-by-one index error: the last item of a list with 4 items is scores[3], not scores[4], and scores[4] raises an IndexError. When in doubt, use scores[-1] for the last item — negative indexes count from the end. Second, the mutable default trap is less common at this stage, but this one is: modifying a list while looping over it. Removing items inside for item in my_list: skips elements because the list shifts under the loop. The safe pattern is to loop over a copy — for item in my_list[:] — or build a new list of the items you want to keep.

Practice: Build a tiny contact book in a file called contacts.py. Store contacts as a list of dictionaries, starting with two contacts you invent (name, phone, email keys). Write three functions: add_contact(contacts) that asks the user for the three fields with input() and appends a new dictionary; find_contact(contacts, name) that loops through and returns the matching dictionary or None; and list_contacts(contacts) that prints each contact on one readable line. At the bottom, write a small menu loop: show options 1) Add, 2) Find, 3) List, 4) Quit, read the user's choice, and call the right function until they quit. Test every option, including searching for a name that does not exist — confirm your program handles it without crashing.

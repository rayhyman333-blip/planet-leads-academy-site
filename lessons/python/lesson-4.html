This lesson teaches you to package code into functions: named, reusable blocks that take inputs and produce outputs. By the end you will define functions with def, pass data in through parameters, send results back with return, and understand the difference between printing and returning. You will also learn about default parameter values and variable scope. Functions are the single most important organizing tool in programming — they let you write a piece of logic once, test it once, and reuse it everywhere without copying and pasting.

You have already been using functions: print(), input(), int(), and len() are all functions that someone else wrote. Defining your own looks like this:

def greet(name):
message = "Hello, " + name + "!"
print(message)

greet("Ava")
greet("Ben")

The def line names the function (greet) and lists its parameters in parentheses — parameters are the inputs the function expects. The indented body runs each time the function is called. Calling greet("Ava") passes "Ava" in as the argument, so name becomes "Ava" for that call, then "Ben" for the next. Parameters make functions flexible: one definition, unlimited uses. A function can take several parameters — def add(a, b): — and the arguments you pass must match in number and order unless you use keyword arguments like greet(name="Ava"), which names each one explicitly.

The return statement sends a value back to the caller, which is different from printing. Compare:

def add(a, b):
return a + b

result = add(3, 4)
print(result) # prints 7
print(result * 2) # prints 14, because result holds the value 7

If add had used print(a + b) instead of return, the 7 would appear on screen but result would hold nothing useful, and result * 2 would fail. The rule of thumb: print() is for showing humans, return is for giving values back to your program so it can keep working with them. A function without a return statement still runs its body, but calling it gives back the special value None. When your function computes something the rest of the program needs — a total, a converted value, a yes/no answer — return it; when it only needs to display something, print it.

Parameters can have default values, which makes them optional: def greet(name, greeting="Hello"): lets you call greet("Ava") for the default or greet("Ava", "Good evening") to override it. Parameters without defaults must come first in the definition. This is how real-world functions offer flexibility without forcing every caller to specify every detail.

Scope determines where a variable can be seen. Variables created inside a function are local: they exist only while the function runs and are invisible outside it. Variables created at the top level of your script are global and readable inside functions. This trips beginners up in one specific way:

count = 0

def increment():
count = count + 1 # ERROR: Python treats count as local here

Because increment assigns to count, Python considers count a local variable throughout the function, so reading it on the right side fails before it is ever set. The fix is to pass values in as parameters and return the new value out — increment(count) returning the updated number — rather than reaching for globals. Keeping data flowing through parameters and return values makes functions predictable and testable, which is why experienced programmers prefer it.

Two mistakes to watch for. First, calling a function before it is defined: Python reads your script top to bottom, so def statements must appear above the lines that call them. Put all your function definitions near the top of the file and the code that uses them at the bottom. Second, forgetting the parentheses when calling: greet without () refers to the function itself and does nothing, while greet("Ava") actually runs it. If your function "does nothing," check for missing parentheses first.

Practice: Write a file called converters.py with three functions: celsius_to_fahrenheit(c) that returns (c * 9/5) + 32, miles_to_km(miles) that returns miles * 1.609, and describe_temperature(c) that takes a Celsius value, converts it using your first function, and returns a string like "25C is 77.0F". Note how the third function calls the first — functions calling functions is normal and encouraged. Then write a small main section at the bottom that asks the user for a Celsius temperature with input(), converts the input with float(), and prints the result of describe_temperature. Test with 0, 25, and 100, and verify the outputs look right.

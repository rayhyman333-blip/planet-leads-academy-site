Lesson 1: Setup and Your First Program

This lesson gets Python running on your computer and teaches you to run your first program. By the end you will know how to check whether Python is already installed, how to install it if it is not, how to experiment in the interactive prompt, and how to save and run a script file. You will also write your first real code: the print() function for showing output, and variables for storing values. Run every example yourself as you read.

First, check whether Python is already installed. Open a terminal and type python3 --version, then press Enter. If you see something like "Python 3.12.1", you are ready. On some Windows setups the command is python --version instead — try that if the first one is not recognized. If neither works, download the installer for your system from python.org and run it. One important detail on Windows: during installation, check the box labeled "Add python.exe to PATH" before clicking Install. That box lets your terminal find Python, and skipping it is the most common reason beginners cannot run the python command afterward.

With Python installed, open the interactive prompt by typing python3 (or python on Windows) with no file name and pressing Enter. You will see a >>> prompt. You type one line, Python runs it immediately and shows the result. Try typing print("Hello, world!") and pressing Enter — Python prints Hello, world! back at you. Try 2 + 3 and you will see 5. Use the prompt as a scratchpad for the whole course: whenever you wonder what a piece of code does, test it here in seconds instead of guessing. To leave the prompt, type exit() and press Enter.

The prompt is great for experiments, but real programs live in script files. Open a plain text editor and type the following two lines, then save the file as hello.py (make sure it ends in .py, not .txt):

print("Hello, world!") print("Welcome to Python.")

Now, in your terminal, move to the folder where you saved the file and run python3 hello.py (or python hello.py on Windows). Both lines print. A script is a saved list of instructions Python runs top to bottom — rerunnable, shareable, and easy to build on. Any plain-text editor works; the free VS Code is a popular choice, and Notepad or TextEdit (in plain text mode) are fine for this course.

The print() function displays values on the screen. The parentheses hold what you want to show, and text must be wrapped in quotes so Python knows it is words, not code: print("Good morning") works, while print(Good morning) is an error because Python looks for something named Good. Separate multiple items with commas — print("My name is", name) prints both with a space between them. Numbers need no quotes: print(42) works fine.

Variables store values under names so you can reuse them. You create one with the = sign, which in programming means "store the value on the right into the name on the left": name = "Maya" stores the text Maya in name, and age = 30 stores the number 30 in age. After that, print(name) shows Maya. Names can contain letters, digits, and underscores, but cannot start with a digit and cannot contain spaces — user_name is fine, 1st_place is not. Python is case-sensitive, so Age and age are two

different variables. You can change a variable later with a new assignment, like age = 31, and the old value is replaced. Build the habit now: clear names like total_price beat x when you reread code next week.

Two beginner mistakes cause most Lesson 1 frustration. First, mixing up the two places you type code: the >>> prompt belongs only in the interactive prompt, so never type it into a script file, and do not include it when running a file from the terminal. Second, small typing slips: Print("hi") fails because Python's function is lowercase print, and print("hi') fails because the opening double quote must be closed with a double quote, not a single one. When something fails, read the error's last line first, fix one thing, and run again.

Practice: Create a file called about_me.py. In it, store your name in a variable called name, your age in a variable called age, and your favorite hobby in a variable called hobby. Then use print() to display three lines, for example "My name is ..." using the variables rather than typing the values directly into the print calls. Run the file from your terminal. Then, in the interactive prompt, try print(name) before defining it and read the error; then define name = "Test" and print it again. Reading errors calmly is a skill you will use in every lesson.

Lesson 2: Data Types, Operators, and User Input

This lesson teaches you the building blocks every Python program is made of: the main data types, the operators that combine them, and how to get input from the person using your program. By the end you will know the difference between strings, integers, floats, and booleans; you will be able to do arithmetic and compare values; and you will write an interactive program that asks the user questions and responds. These ideas appear in every lesson after this one, so make sure each example below runs on your machine before moving on.

Python has a few core data types you will use constantly. A string (str) is text in quotes: "hello", 'Python', "42". An integer (int) is a whole number: 7, -3, 1000. A float is a number with a decimal point: 3.5, -0.25, 98.6. A boolean (bool) is one of two values, True or False, written with a capital first letter — these represent yes/no answers and become important in Lesson 3. You can ask Python what type a value is with the type() function: type("hello") shows <class 'str'> and type(3.5) shows <class 'float'>. Types matter because Python treats "42" (text) and 42 (a number) very differently, as you will see with operators next.

Operators combine values into new values. Arithmetic operators work like a calculator: + adds, - subtracts, * multiplies, and / divides. Two are special: // does floor division (7 // 2 gives 3, the whole part), % gives the remainder (7 % 2 gives 1), and ** raises to a power (2 ** 3 gives 8). The + operator on strings joins them together, which is called concatenation: "Good " + "morning" gives "Good morning". You can repeat a string with *: "ha" * 3 gives "hahaha". But "5" + 3 is an error — Python will not silently mix text and numbers. Convert explicitly: str(3) makes text, while int("5") and float("5.5") make numbers. Explicit conversion prevents a whole category of bugs.

Comparison operators ask questions and answer with booleans. == checks equality (5 == 5 is True), != checks inequality, and <, >, <=, >= compare size. Note the double equals: a single = stores a value in a variable, while == compares two values — mixing them up is one of the most common beginner errors in any language. Comparisons also work on strings, where they compare alphabetically: "apple" < "banana" is True. Logical operators combine booleans: and is True only if both sides are True, or is True if either side is True, and not flips a value. So (age >= 18) and (has_ticket == True) is True only when both conditions hold, and you will use these constantly to make decisions in Lesson 3.

The input() function makes your programs interactive. When Python reaches name = input("What is your name? "), it displays the question, waits for the user to type a response and press Enter, then stores whatever was typed — always as a string — in name. Try this small program:

name = input("What is your name? ") print("Nice to meet you,", name + "!")

Run it and type your name when asked. The catch: input() always returns a string, so age = input("How old are you? ") followed by age + 1 crashes. Convert first: age = int(input("How old are you? ")). If the user types non-numeric text, int() raises an error — Lesson 6 will teach you to handle that gracefully.

Two mistakes to watch for in this lesson. First, forgetting that input() returns a string and then doing arithmetic on it — convert with int() or float() before calculating. Second, using = when you mean ==: writing if age = 18 instead of if age == 18 is a syntax error in a comparison, and in plain code x = 5 changes x when you only meant to check it. A good habit: read = as "gets" (x gets 5) and == as "equals" (x equals 5), and your brain will flag the mix-up.

Practice: Write a program called bill_splitter.py that asks the user for the total bill amount (convert it to a float), asks how many people are splitting it (convert to an int), calculates each person's share, and prints a friendly message like "Each person pays 23.5". Test it with a bill of 100 split 4 ways. Then type non-numeric text at a prompt and read the error — note the phrase "invalid literal", which tells you the conversion failed. Finally, experiment in the interactive prompt: evaluate "10" + "20", then 10 + 20, then int("10") + 20, and make sure you can explain why each result is what it is.

Lesson 3: Control Flow — Decisions and Loops

This lesson teaches your programs to make decisions and repeat work — the two abilities that turn a calculator into a real program. By the end you will write if/elif/else statements that choose between paths, for loops that repeat a fixed number of times or walk through collections, and while loops that repeat until a condition changes. You will also learn break and continue for controlling loops from the inside. Control flow is where programs start to feel intelligent, and nearly every script you write from now on will use it.

An if statement runs a block of code only when its condition is True:

age = int(input("Enter your age: ")) if age >= 18: print("You are an adult.") print("Welcome!") else: print("You are under 18.")

Notice the colon at the end of the if line and the four-space indentation of the lines underneath — indentation is how Python knows which lines belong to the if. The else branch runs when the condition is False. For more than two paths, add elif (short for "else if") branches between them:

score = int(input("Enter your score: ")) if score >= 90: print("Grade: A") elif score >= 80: print("Grade: B") elif score >= 70: print("Grade: C") else: print("Grade: below C")

Python checks the branches top to bottom and runs the first one whose condition is True, then skips the rest — so order matters, and the most specific or highest condition should come first. You can combine conditions with and, or, and not from Lesson 2, for example if temperature > 30 and sunny:.

A for loop repeats a block a known number of times or once per item in a collection. The range() function generates number sequences: for i in range(5): runs with i equal to 0, 1, 2, 3, 4 — five times total, starting at 0. That zero start surprises beginners, so remember: range(5) means "the five numbers starting at 0". You can also loop directly over items, which you will do constantly once Lesson 5 introduces lists:

for name in ["Ava", "Ben", "Cara"]: print("Hello,", name)

Each time through, the loop variable takes the next value. Indentation again marks the loop body — every indented line under the for repeats, and the first unindented line after it runs once when the loop finishes.

A while loop repeats as long as its condition stays True, which makes it ideal when you do not know in advance how many repetitions you need:

attempts = 0 password = "" while password != "secret123": password = input("Enter the password: ") attempts = attempts + 1 print("Unlocked after", attempts, "attempts.")

The danger with while is the infinite loop: if the condition can never become False, the loop runs forever. Always make sure something inside the loop body moves the condition toward False — here, each input gives the user a chance to type the right password. If you ever get stuck in an infinite loop, press Ctrl+C in the terminal to stop the program. Two tools give you finer control: break exits the loop immediately, and continue skips the rest of the current pass and jumps to the next one. For example, break can end a guessing game the moment the player wins, and continue can skip blank lines while processing input.

Two mistakes dominate this lesson. First, indentation errors: mixing tabs and spaces, or indenting inconsistently, causes IndentationError. Pick one style — four spaces, which most editors insert when you press Tab — and stay consistent. Second, the classic off-by-one error with range(): range(10) gives 0 through 9, not 1 through 10, so if you need 1 through 10 use range(1, 11). When a loop runs the wrong number of times, add a temporary print(i) inside it to watch the values — seeing the actual sequence usually reveals the mistake instantly.

Practice: Write a number-guessing game called guess.py. Pick a secret number in the code (for example secret = 7). Use a while loop to keep asking the user for a guess until they get it right. After each wrong guess, print "Too high!" or "Too low!" using if/elif/else, and count the attempts. When they guess correctly, break out of the loop and print how many tries it took. Then, as a second exercise, write a for loop that prints the 7-times table from 7 x 1 to 7 x 12, and a third small script that uses a for loop over a list of three of your favorite foods to print "I like ..." for each one.

Lesson 4: Functions — Reusable Blocks of Code

This lesson teaches you to package code into functions: named, reusable blocks that take inputs and produce outputs. By the end you will define functions with def, pass data in through parameters, send results back with return, and understand the difference between printing and returning. You will also learn about default parameter values and variable scope. Functions are the single most important organizing tool in programming — they let you write a piece of logic once, test it once, and reuse it everywhere without copying and pasting.

You have already been using functions: print(), input(), int(), and len() are all functions that someone else wrote. Defining your own looks like this:

def greet(name): message = "Hello, " + name + "!" print(message)

greet("Ava") greet("Ben")

The def line names the function (greet) and lists its parameters in parentheses — parameters are the inputs the function expects. The indented body runs each time the function is called. Calling greet("Ava") passes "Ava" in as the argument, so name becomes "Ava" for that call, then "Ben" for the next. Parameters make functions flexible: one definition, unlimited uses. A function can take several parameters — def add(a, b): — and the arguments you pass must match in number and order unless you use keyword arguments like greet(name="Ava"), which names each one explicitly.

The return statement sends a value back to the caller, which is different from printing. Compare:

def add(a, b): return a + b

result = add(3, 4) print(result) # prints 7 print(result * 2) # prints 14, because result holds the value 7

If add had used print(a + b) instead of return, the 7 would appear on screen but result would hold nothing useful, and result * 2 would fail. The rule of thumb: print() is for showing humans, return is for giving values back to your program so it can keep working with them. A function without a return statement still runs its body, but calling it gives back the special value None. When your function computes something the rest of the program needs — a total, a converted value, a yes/no answer — return it; when it only needs to display something, print it.

Parameters can have default values, which makes them optional: def greet(name, greeting="Hello"): lets you call greet("Ava") for the default or greet("Ava", "Good evening") to override it. Parameters without defaults must come first in the definition. This is how real-world functions offer flexibility without forcing every caller to specify every detail.

Scope determines where a variable can be seen. Variables created inside a function are local: they exist only while the function runs and are invisible outside it. Variables created at the top level of your script are global and readable inside functions. This trips beginners up in one specific way:

count = 0

def increment(): count = count + 1 # ERROR: Python treats count as local here

Because increment assigns to count, Python considers count a local variable throughout the function, so reading it on the right side fails before it is ever set. The fix is to pass values in as parameters and return the new value out — increment(count) returning the updated number — rather than reaching for

globals. Keeping data flowing through parameters and return values makes functions predictable and testable, which is why experienced programmers prefer it.

Two mistakes to watch for. First, calling a function before it is defined: Python reads your script top to bottom, so def statements must appear above the lines that call them. Put all your function definitions near the top of the file and the code that uses them at the bottom. Second, forgetting the parentheses when calling: greet without () refers to the function itself and does nothing, while greet("Ava") actually runs it. If your function "does nothing," check for missing parentheses first.

Practice: Write a file called converters.py with three functions: celsius_to_fahrenheit(c) that returns (c * 9/5) + 32, miles_to_km(miles) that returns miles * 1.609, and describe_temperature(c) that takes a Celsius value, converts it using your first function, and returns a string like "25C is 77.0F". Note how the third function calls the first — functions calling functions is normal and encouraged. Then write a small main section at the bottom that asks the user for a Celsius temperature with input(), converts the input with float(), and prints the result of describe_temperature. Test with 0, 25, and 100, and verify the outputs look right.

Lesson 5: Lists, Dictionaries, Tuples, and Sets

This lesson teaches you Python's four core collection types — containers that hold multiple values. By the end you will create and manipulate lists, look up values in dictionaries by key, understand when tuples and sets are the right choice, and loop over collections with for. Collections are what let programs handle real-world quantities of data: instead of one variable per item, you keep hundreds of items in a single structure and process them with loops and functions from the previous lessons.

A list is an ordered, changeable collection written with square brackets: scores = [85, 92, 78, 90]. Items are numbered starting at 0, so scores[0] is 85 and scores[2] is 78. You can read the length with len(scores), add items with scores.append(88), remove by value with scores.remove(78), or grab and remove the last item with scores.pop(). Lists can hold mixed types, but keeping one type per list makes your code easier to reason about. Looping is where lists shine: for score in scores: visits each item in order. Slicing grabs a section — scores[1:3] gives [92, 78] — handy for "first five" or "everything after the header" style tasks.

A dictionary stores key-value pairs inside curly braces: person = {"name": "Ava", "age": 30, "city": "Austin"}. Instead of positions, you look things up by key: person["name"] gives "Ava". Add or change entries with person["email"] = "ava@example.com", remove with del person["city"], and check existence safely with person.get("phone", "unknown") — get() returns a default instead of crashing when the key is missing, which makes it the safer choice for lookups. Dictionaries model real things beautifully: a contact has a name, phone, and email; a product has a price and a stock count. Loop over keys with for key in person:, over values with for value in person.values():, and over both with for key, value in person.items():. The expense tracker in Lesson 8 stores each expense as a dictionary inside a list — a pattern you will see in real programs everywhere.

A tuple is like a list that cannot be changed, written with parentheses: point = (10, 20). You read items the same way — point[0] is 10 — but point[0] = 5 is an error. Use tuples for fixed collections that should never change accidentally: coordinates, RGB colors, or a function's multiple return values. In fact, a function can return several values at once — return width, height actually returns one tuple — and the caller can unpack it: w, h = get_size(). A set is an unordered collection of unique values written with curly braces: tags = {"python", "coding", "python"} automatically becomes {"python", "coding"}, dropping the duplicate. Sets answer membership questions fast ("python" in tags) and do math-like operations: set_a | set_b unions them, set_a & set_b intersects them. Reach for a set whenever duplicates would be wrong or you need fast "is it in there" checks.

Choosing between them gets easier with a simple guide. Need order and the ability to change items? List. Need to look things up by name rather than position? Dictionary. Have values that must never change? Tuple. Need uniqueness or membership tests? Set. Beginners often force everything into lists, then write awkward code searching for items by position — if you catch yourself keeping a parallel list of names just to find the matching data, that is a dictionary's job.

Two mistakes are classic here. First, the off-by-one index error: the last item of a list with 4 items is scores[3], not scores[4], and scores[4] raises an IndexError. When in doubt, use scores[-1] for the last item — negative indexes count from the end. Second, the mutable default trap is less common at this stage, but this one is: modifying a list while looping over it. Removing items inside for item in my_list: skips elements because the list shifts under the loop. The safe pattern is to loop over a copy — for item in my_list[:] — or build a new list of the items you want to keep.

Practice: Build a tiny contact book in a file called contacts.py. Store contacts as a list of dictionaries, starting with two contacts you invent (name, phone, email keys). Write three functions: add_contact(contacts) that asks the user for the three fields with input() and appends a new dictionary; find_contact(contacts, name) that loops through and returns the matching dictionary or None; and list_contacts(contacts) that prints each contact on one readable line. At the bottom, write a small menu loop: show options 1) Add, 2) Find, 3) List, 4) Quit, read the user's choice, and call the right function until they quit. Test every option, including searching for a name that does not exist — confirm your program handles it without crashing.

Lesson 6: Files and Error Handling

This lesson teaches your programs to remember things between runs by reading and writing files, and to survive problems gracefully with error handling. By the end you will open, read, and write text files using the with statement; store structured data with JSON; and wrap risky code in try/except so one bad input does not crash your whole program. These two skills together are what make the capstone projects in Lessons 7 and 8 possible: real programs persist data and handle the unexpected.

Reading a file takes three ideas: open it, read from it, and close it — and the with statement handles the closing for you automatically:

with open("notes.txt", "r", encoding="utf-8") as f: content = f.read() print(content)

The "r" means read mode, and encoding="utf-8" handles international characters correctly — make it a habit in every open() call. Alternatives to f.read(), which grabs everything at once: f.readline() reads a single line, and for line in f: loops over the file line by line, which is the memory-friendly way to process large files. Writing is symmetric: open("notes.txt", "w", encoding="utf-8") opens in write mode and f.write("hello\n") saves text, where \n inside the string means "new line". But beware: "w" erases the file's previous contents. Use "a" (append) mode to add to the end without erasing. The single most common file mistake is writing with "w" when you meant "a" and losing data, so pause and double-check the mode letter every time you write.

For structured data, JSON is the standard choice: it stores lists and dictionaries as text that both humans and programs can read. Python's json module converts directly:

import json

expenses = [{"item": "groceries", "amount": 42.50}, {"item": "bus fare", "amount": 3.00}] with open("expenses.json", "w", encoding="utf-8") as f: json.dump(expenses, f, indent=2)

with open("expenses.json", "r", encoding="utf-8") as f: loaded = json.load(f)

json.dump writes the Python object to the file (indent=2 makes it human-readable), and json.load reads it back into the identical structure. This read-process-write cycle is the backbone of countless real programs: load the data, let the user change it, save it back. The expense tracker in Lesson 8 uses exactly this pattern, so make sure you can run the snippet above and open expenses.json in your editor to see the readable result.

Error handling keeps programs alive when things go wrong. Without it, one bad input crashes everything: age = int(input("Age: ")) fails if the user types "twenty". With try/except, you attempt the risky operation and define a fallback:

try: age = int(input("Age: ")) print("Next year:", age + 1) except ValueError: print("Please type a whole number.")

If int() fails, Python jumps to the except block instead of crashing. Catch specific exceptions (ValueError for bad conversions, FileNotFoundError for missing files, ZeroDivisionError for division by zero) rather than a bare except:, because catching everything hides bugs you actually want to see. You can stack handlers for different error types, add an else: block that runs only when no error occurred, and a finally: block for cleanup code that must run either way. A practical pattern combines both halves of this lesson: try to load a data file, and if it does not exist yet, start with empty data instead of

crashing:

try: with open("expenses.json", "r", encoding="utf-8") as f: expenses = json.load(f) except FileNotFoundError: expenses = []

The first time the program runs there is no file, so it starts fresh; every later run loads the saved data. That tiny pattern is the difference between a toy script and a program that remembers.

Two mistakes to avoid. First, forgetting encoding="utf-8" and then hitting mysterious errors with accented names or text in other languages — include it in every open() call from now on. Second, using try/except as a substitute for checking: wrapping huge blocks of code in one try hides where the real problem is. Keep the try block small — just the risky lines — and handle the error right next to it, so the error message still points at the true cause.

Practice: Write diary.py, a tiny journal program. When run, it asks the user for one line of journal text with input(), then appends it to diary.txt along with today's date (import datetime and use datetime.date.today()). Opening the file in append mode ("a") creates it automatically if it does not exist, so the first run works without special handling — but also add a "read" feature: if the user types the word "read" instead of a journal entry, open the file in read mode inside try/except FileNotFoundError and either print the whole diary or print a friendly "no entries yet" message. Test by adding two entries, reading them back, deleting the file, and running once more to confirm the empty-diary case is handled gracefully.

Lesson 7: Automation Project — Build a File Organizer

This lesson is your first real project: an automation script that organizes a messy folder for you, sorting files into subfolders by type. By the end you will have planned a script before coding it, used the os and shutil modules to inspect and move files, built the program in small testable steps, and — most importantly — added a dry-run mode so you can preview changes before anything moves. This is the moment the course shifts from exercises to software that does genuinely useful work on your computer.

Every good automation starts on paper, not in code. Our goal: given a messy folder like Downloads, move every file into a subfolder named for its type — Images, Documents, Audio, Archives — and leave files we have no rule for untouched. The plan breaks into steps: 1) list everything in the folder; 2) for each item, skip it if it is not a file (we do not want to move our new subfolders into themselves); 3) look at the file's extension; 4) find which category that extension belongs to; 5) create the category folder if it does not exist; 6) move the file there. Writing the steps in plain language first is called pseudocode, and it turns "build a file organizer" from an intimidating blob into six small problems you already know how to solve.

Python's os module talks to your operating system. The three functions we need: os.scandir(folder) lists a folder's entries, entry.is_file() tells files apart from folders, and os.path.splitext(name) splits "photo.jpg" into ("photo", ".jpg") so we can read the extension. The shutil module moves files: shutil.move(source, destination). Here is the core loop, and you should type it and run it against a test folder before adding anything else:

import os import shutil

TARGET = os.path.expanduser("~/Downloads") RULES = { "Images": {".jpg", ".jpeg", ".png", ".gif"}, "Documents": {".pdf", ".txt", ".md"}, "Audio": {".mp3", ".wav"}, "Archives": {".zip"}, }

for entry in os.scandir(TARGET): if not entry.is_file(): continue name, ext = os.path.splitext(entry.name) ext = ext.lower() for category, extensions in RULES.items(): if ext in extensions: dest_dir = os.path.join(TARGET, category) os.makedirs(dest_dir, exist_ok=True) shutil.move(entry.path, os.path.join(dest_dir, entry.name)) print("Moved", entry.name, "->", category) break else: print("Skipped (no rule):", entry.name)

Several lesson ideas combine here: the for loop from Lesson 3, the dictionary of sets from Lesson 5, the for/else pattern (the else runs only if the inner loop never hit break — a neat way to say "no rule matched"), and exist_ok=True which creates the folder only if needed instead of crashing when it already exists. Test this on a COPY of a folder first, or a test folder with a few spare files — never develop file-moving code directly on your real Downloads until you trust it.

The professional upgrade is a dry-run mode: a flag that prints what would happen without moving anything. This is how real automation is built safely — preview first, execute second:

DRY_RUN = True # set to False when you trust the preview

category) else: os.makedirs(dest_dir, exist_ok=True) shutil.move(entry.path, os.path.join(dest_dir, entry.name)) print("Moved", entry.name, "->", category)

Run with DRY_RUN = True, read the preview carefully, and only flip it to False when every line looks right. Extend the script yourself: add more extensions to RULES (a "Spreadsheets" category for .csv files is a good one), or handle name collisions — what happens if two files named notes.txt land in Documents? (shutil.move will overwrite, so a real improvement is renaming the second one to notes_2.txt.) Thinking about what can go wrong and coding the answer is exactly what separates scripts from reliable tools.

Two mistakes are common in automation work. First, running destructive code on real data during development — always build against a test folder with copies, and use dry-run mode, until the script has earned your trust. Second, hard-coding paths like "C:\Users\Maya\Downloads" that break on other computers; os.path.expanduser("~") finds the current user's home folder on any system, and os.path.join builds paths with the correct separators. Portable code is professional code.

Practice: Build the organizer step by step in a file called organizer.py. Step 1: write only the listing loop that prints each file's name and extension — run it and confirm the output. Step 2: add the RULES dictionary and the category-matching logic, printing "Would move X -> Y" without moving anything. Step 3: add the DRY_RUN flag and the real move code, run a preview against a test folder containing at least six files of different types (create them yourself — they can be empty), verify the preview, then set DRY_RUN = False and run it for real. Step 4 (stretch): add a "Misc" rule or collision-safe renaming so no file is ever silently overwritten. Keep this script — it is the first genuinely useful program in your portfolio.

Lesson 8: Capstone — Expense Tracker CLI and Where to Go Next

This final lesson puts the whole course together in one capstone project: a command-line expense tracker that adds expenses, lists them, shows totals, and saves everything to a file so nothing is lost when the program closes. By the end you will have combined functions, loops, dictionaries, JSON storage, and error handling in one file, and tested it like a user would. It closes with a map of where to go next.

Start every project by listing features in plain language before writing code. Our expense tracker needs four: 1) add an expense (description, amount, category); 2) list all expenses; 3) show the total spent, and totals per category; 4) save to a JSON file on every change and load it at startup. Each maps to a lesson: input() and functions (Lessons 2 and 4), the menu loop (Lesson 3), a list of dictionaries (Lesson 5), JSON and try/except (Lesson 6). Asking "which lesson taught this piece?" is how you break big projects down.

Here is the data layer, the foundation everything else uses:

import json

DATA_FILE = "expenses.json"

def load_expenses(): try: with open(DATA_FILE, "r", encoding="utf-8") as f: return json.load(f) except FileNotFoundError: return []

def save_expenses(expenses): with open(DATA_FILE, "w", encoding="utf-8") as f: json.dump(expenses, f, indent=2)

Each expense is a dictionary like {"description": "groceries", "amount": 42.50, "category": "food"}, and the whole tracker is a list of those dictionaries. load_expenses handles the first-run case by returning an empty list when the file does not exist yet — the exact pattern from Lesson 6. Keep these two functions small and correct before building anything on top of them; test them in the interactive prompt by saving a sample list and loading it back.

The feature functions operate on the in-memory list, and the menu loop ties it all together:

def add_expense(expenses): description = input("Description: ") try: amount = float(input("Amount: ")) except ValueError: print("That is not a valid number — expense not added.") return category = input("Category: ") expenses.append({"description": description, "amount": amount, "category": category}) save_expenses(expenses) print("Added.")

def show_total(expenses): total = sum(e["amount"] for e in expenses) print("Total spent:", round(total, 2))

def main(): expenses = load_expenses() while True: print("\n1) Add 2) List 3) Total 4) Quit") choice = input("Choose: ") if choice == "1": add_expense(expenses) elif choice == "2": for e in expenses: print(e["description"], "-", e["amount"], "(" + e["category"] + ")") elif choice == "3": show_total(expenses) elif choice == "4": print("Goodbye!") break else: print("Unknown choice, try 1-4.")

main()

Notice the architecture: main() owns the loop and the data, each feature function does one job, and saving happens inside add_expense right after the change, so data survives an unexpected quit. Error handling sits exactly where user input enters — the float conversion — not wrapped around the whole program.

Two capstone-level mistakes to watch for. First, forgetting to save after a change — if listing works but quitting loses data, you are displaying the in-memory list fine but never called save_expenses after adding. A good rule: every function that mutates the data saves it before returning. Second, letting main() sprawl: if your loop body grows longer than a screen, extract a function — the add_expense/show_total split is the pattern to copy.

Natural extensions, each an evening's work: per-category totals, deleting an expense by number, editing an entry, or a monthly report filtered by a "date" field you add to each expense. Each reuses the same architecture — programs grow by adding small functions, not by rewriting.
